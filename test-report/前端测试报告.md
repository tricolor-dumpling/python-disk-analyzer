## 3. 重要环境发现：为什么「Everything IPC 尚未就绪」

实测排查链条（供开发者参考，报告问题 P1-1 的背景）：

1. `/api/health` 返回 `ready:false`；直接 ctypes 调 SDK 得 `query_ok=0, last_error=2`（`EVERYTHING_ERROR_IPC`）；
2. `Get-Process Everything` 显示进程存在（PID 4972），但 **SessionId = 0**（服务会话），且枚举不到任何 Everything 窗口（`FindWindow("EVERYTHING_TASKBAR_NOTIFICATION")=0`、EnumWindows 无结果）；
3. 结论：当前机器上只有 **Session 0 的后台/服务实例**在跑，用户会话中没有可供 SDK IPC（窗口消息）通信的 Everything 客户端窗口，因此所有 SDK 查询一律报错码 2。

这本身不是本项目的 bug，但暴露了一个产品缺口：**工具检测到了「未就绪」，却没有告诉用户最可能的原因和恢复动作**（打开一次 Everything 主程序即可）。目前唯一的相关提示藏在首启引导第 1 步里，且错误发生时不再重复出现。

## 4. 问题清单

### P1-1 所有失败路径都把内部错误码直接抛给用户，且无恢复指引
- **现象**（实测复现）：页面加载即红色横幅「扫描失败: Everything查询失败: 2」；点「开始全量扫描」状态行变「全量扫描失败：Everything查询失败: 2」；点「开始对比」变「当前扫描失败: Everything查询失败: 2」。三处文案相同、均无行动指引。
- **根因**：
  - 后端 `scan.py:181` `raise RuntimeError(f"Everything查询失败: {everything.Everything_GetLastError()}")` 把原始错误码拼进消息；
  - 前端 `app.js`（`browsePath/showBrowseError`、`renderFullscanState`、`compareSnapshots`）原样展示 `e.message`。
- **影响**：用户不知道「2」是什么、该干什么。本次环境下真实解法是「打开一次 Everything 主程序」，但界面没有任何地方说。
- **建议**：
  1. 建立「错误码 → 中文文案 + 恢复动作」映射表（如 2 → 「无法连接 Everything。请打开 Everything 主程序并等待索引加载后重试；若你以管理员身份运行了 Everything，请以相同权限启动本工具」）；
  2. 错误横幅内附「重试」按钮之外再加「查看帮助」（跳转引导条或文档锚点）。

### P1-2 排行视图中点击「文件行」触发整个目录的重复扫描请求
- **现象**（实测复现）：排行视图下点击任意文件行，抓包看到重新发出了 `POST /api/browse {root:当前目录,…}` —— 加载动画闪现、状态行重置；Everything 可用时等于白扫一遍大目录。
- **根因**：`app.js:299` 渲染时文件行的 `data-path` 为空字符串但仍绑定了 click：`body.querySelectorAll(".ranking-row[data-path]")` 会同时选中 `data-path=""` 的文件行；点击后 `browsePath("")` 在 `app.js:367` 回退为 `currentRoot`，造成对当前目录的完整重复请求。
- **建议**：文件行不绑定进入逻辑（渲染时区分 `data-browsable` 或 click 内判断 `entry.is_dir === false` 直接 return）；或给文件行加「所在目录」/「复制路径」等有意义的行为。

### P2-1 首屏在 Everything 未就绪时直接呈现报错横幅，第一印象差
- **现象**：新用户首次打开页面，自动浏览 D:\ 失败，欢迎引导下面就是一条红色错误。
- **根因**：`app.js init()`（L1003 起）无条件执行 `browsePath(firstRoot, true)`，不参考 `/api/health` 的结果。
- **建议**：init 先 await refreshHealth()；`ready=false` 时跳过自动浏览，改为在浏览卡片显示引导态（「Everything 未就绪 → 打开主程序 → 点此重试」），把报错留给用户主动触发的动作。

### P2-2 「撤销最近保存」在无任何会话时也可点，确认后才报错
- **现象**：把历史删光后按钮仍高亮可用；点击 → 弹「不可恢复」确认框 → 确认后才 toast「没有可撤销的保存记录」。用危险样式弹窗去承载一个必然失败的操作，惊吓度大于信息量。
- **根因**：`app.js:230` 按钮无 disabled 逻辑；`undoLastSave()` 先弹确认再调 API。
- **建议**：`refreshSnapshots()` 后按 `sessionsCache.length === 0` 禁用按钮（title 说明原因）；或先查再弹窗。

### P2-3 浏览输入框接受文件路径，「浏览根」被静默污染成文件
- **现象**（实测复现）：输入 `C:\Windows\System32\drivers\etc\hosts` 点「浏览」→ 报 IPC 错误（掩盖了真实问题）；且 `currentRoot` 已被设成该文件路径，后续其它交互全部基于错误的根。
- **根因**：`app.js:949-956` btn-browse 把任意非空输入赋给 currentRoot；后端 `app.py:141-145` 只校验 `exists()` 不校验 `is_dir()`。
- **建议**：后端 browse 对非目录返回明确错误「不是一个目录：xxx」；前端收到后将输入框回退为上一个有效根。

### P2-4 健康徽章是纯装饰性入口，不可发现其可点击
- **现象**：徽章 title 写着「点击查看 Everything 状态」，但视觉上无 hover/指针差异暗示（实测它绑定 openSettings）。设置里才有 DLL 路径等诊断信息。
- **建议**：给徽章加 hover 态与下拉小面板（状态/DLL 路径/「打开帮助」）；或未就绪时徽章自动呼吸闪烁提醒可点。

### P2-5 全量扫描的反馈时序混乱：「已启动」toast 之后紧跟失败
- **现象**：点击开始 → 绿色/蓝色 toast「全量扫描已启动」→ 约 1 秒后状态行红字「全量扫描失败：…」。两条信息方向相反。
- **根因**：`startFullscan()`（app.js:495）在 POST 成功返回后立刻 toast；后台线程随后的失败只体现在轮询状态行。
- **建议**：去掉「已启动」toast（进度条+状态行已足够），或在 toast 中改用中性文案「全量扫描任务已提交」。

### P2-6 筛选词跨目录残留，空态文案误导
- **现象**（实测复现）：筛选框输入 windows 后浏览其它目录（或注入数据渲染），列表为空时显示「这里没有找到子目录或文件」——实际是筛选过滤掉了全部条目，目录并非为空。
- **根因**：`filteredEntries()`（app.js:269）始终应用全局筛选；`renderEntries()` 的空态只有一种文案。
- **建议**：`query` 非空时空态改为「无匹配“windows”的结果（清除筛选）」并提供一键清除；或浏览新路径时自动清空筛选。

### P3-7 对比功能不显示「将对比哪个根」，易触发跨根错误
- **现象**：基线下拉混列 C: 与 D: 的快照；对比 root 取自当前浏览位置（`app.js:719` `root: currentRoot || currentPath`）。用户浏览着 C:\ 却选了 D 盘基线 → 后端 `compare.diff_from_current` 以跨盘为由拒绝（compare.py:18 设计如此，数据安全没问题），但用户视角是莫名其妙报错。
- **建议**：在对比区显式标注「将对【当前根】与所选基线对比」；快照列表每一条上加「对比此快照」按钮，自动带上对应 root，绕开自由文本路径输入。

### P3-8 弹窗缺少焦点陷阱与焦点归还
- **现象**：打开设置/确认弹窗后按 Tab，焦点会穿透到底层页面控件；关闭弹窗后焦点不回到触发按钮。键盘用户体验断裂。
- **根因**：`bindModalClose()`（app.js:900）只处理关闭事件，无 focus management。
- **建议**：openModal 时保存 `document.activeElement` 并聚焦面板首个可聚焦元素，Tab 循环限制在面板内，closeModal 时归还焦点。（约 30 行代码可封装）

### P3-9 R 快捷键在弹窗打开时仍触发后台重新浏览
- **现象**：设置弹窗开着按 R，弹窗后面悄悄发起了 /api/browse 请求。
- **根因**：`keydown` 处理（app.js:918）只排除输入类焦点元素，未检查是否有弹窗打开。
- **建议**：快捷键统一前置判断 `document.querySelector('.modal:not(.hidden)')` 存在则忽略。

### P3-10 工程健壮性小项（合并报告）
1. **Esc 关闭顺序写死** 为 `["wipe-modal","confirm-modal","settings-modal"]`（app.js:924），与实际打开顺序可能不一致；建议维护打开栈。
2. **每次根级浏览都 POST 整份 settings** 写 config.json（app.js:450），频繁切盘产生多余磁盘 IO；建议防抖 300ms。
3. **`window.__lastBrowseData`** 用全局变量在函数间传数据（app.js:294 等），建议收敛到模块内 state 对象。
4. **刷新页面后「是否保存」提示会再次弹出**：`handledScanVersion` 不持久化（app.js:458），`result_ready && !saved` 时用户点过「暂不保存」后刷新又会被问一遍；可在 localStorage 记录已处理的 scan_version。
5. **`/api/settings` POST 任意键合并进配置**（app.py:445-447 `config.update(data)`），脏键永久留存于 config.json；建议白名单过滤。

### 前端自动化测试缺失（工程建议）
后端 API 有 34 个用例（`tests/test_web.py`）覆盖良好，但 `web/static/js/app.js` 1030 行交互逻辑零测试——本次发现的 P1-2 这类回归最适合用 jsdom/vitest 锁住。建议至少为「文件行点击」「筛选空态」「弹窗焦点」补 3 个冒烟用例。

## 5. 做得好的地方（保持）

- **XSS 防线一致**：所有插值均经 `esc()`，含 title/aria-label 属性；
- **危险操作双保险**：一键清空需输入「确认清空」四字，按钮禁用态联动正确（实测通过）；
- **扫描中的降级设计**：已完成盘可即时浏览、进行中盘给出友好占位（`api_browse` 分支 ①②③ 层次清晰）；
- **无障碍基础**：`role=status/region/button`、`aria-live`、`aria-pressed`、`:focus-visible`、`prefers-reduced-motion` 均有覆盖；
- **细节体验**：Ctrl+K 快捷搜索、R 刷新、浏览历史 chips、紧凑列表、document.title 跟随路径变化；
- **安全边界**：服务仅绑定 127.0.0.1，本地单用户场景下风险可控。
