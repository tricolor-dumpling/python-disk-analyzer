# 用户实测迭代意见（2026-08-26）

> 测试身份：真实用户视角，非代码走查。环境：Windows + Python 3.14.3（项目 .venv）+ Everything 常驻（C 盘 41.2 万 / D 盘 13.8 万条索引记录）。
> 实测范围：CLI 非交互全参数、Web 端完整旅程（浏览 → 全量扫描 → 保存快照 → 撤销 → 对比 → 导出 → 设置）、单测复核。
> 总体结论：**工程质量高于同类小工具平均水平**（原子写、台账回滚、Host 白名单、异机基线拦截、退出码契约都很扎实），但发现 **1 个 P0 性能缺陷**（Web 对比假死约 5 分钟）与 **1 个健壮性缺陷**（默认导出路径失败时裸 traceback），建议优先处理。

---

## 一、P0 · 必修

### 1. Web「历史对比」大盘根场景假死（compare.py `_merge` leaf_only 分支 O(N²)）

**现象**：Web 端对 D:\ 全量结果与基线快照对比，请求超过 300 秒无响应；期间前端无任何进度或超时提示，用户只会认为"卡死了"。CLI `--baseline` 与 TUI `H` 不受影响（未启用该分支），因此三端行为不一致且问题隐蔽。

**定位**：`compare.py:129-143`。`leaf_only=True` 时对全部路径键做**两两前缀比较**：

```python
leaves = {p for p in keys if not any(
    q != p and os.path.normcase(q).startswith(os.path.normcase(p).rstrip("\\") + "\\")
    for q in keys)}
```

16,110 × 16,120 ≈ **2.6 亿次** `normcase + startswith`，且 `normcase(q)` 在内层循环反复重算。

**实测量化**（本机，合成数据外推 + faulthandler 栈证实卡在 `ntpath.normcase`）：

| 规模 n | 耗时 | 外推到 16,110 行 |
|---|---|---|
| 1,000 | 1.12 s | ≈ 291 s |
| 2,000 | 4.27 s | ≈ 277 s |
| 4,000 | 16.6 s | ≈ 269 s |

即：**对盘根级快照（数万目录），每次点「开始对比」都是约 5 分钟的纯 CPU 假死**；用户连点几次还会在 Flask 里堆积多个卡死的 worker 线程。

**修复建议**：
- 把 normcase 结果预计算一次（`norm = [os.path.normcase(p) for p in keys]` 后排序），叶子判定用排序邻居或 bisect 前缀检查；
- 或改为「标记祖先」法：每个键向上回溯父目录（`Path.parent` 循环至根），命中的祖先从候选集剔除，复杂度 O(N×深度)，1.6 万行应在 **<0.5 秒**；
- 补一条性能回归护栏：≥2 万行合成键集合下 leaf 过滤 ≤1 秒（现有 test_compare 只有 4 行夹具，永远测不出规模问题）；
- Web 层面对比请求加服务端耗时上限/进度反馈，「对比中」状态可取消。

### 2. CLI 默认导出路径写入失败时裸 traceback + 用户找不到导出文件

**现象**（实测复现）：`--export csv` 不带 `--output` 时，`cli.py:446` 在 try/except OSError **之外**调用 `_default_export_path()`，其内部 `mkdir` 抛出的 `PermissionError` 直接以裸 traceback 崩出——与 cli.py 模块文档承诺的"写文件失败打印中文提示并退出码 1"不符：

```
File "cli.py", line 562, in _default_export_path
    base.mkdir(parents=True, exist_ok=True)
PermissionError: [WinError 5] 拒绝访问。: 'C:\\Users\\Laptop\\AppData\\Local\\PythonDiskScanner\\exports'
```

连带两个体验问题：
- **README 与实现不一致**：README 说默认"在当前目录自动命名"，实际写到 `%LOCALAPPDATA%\PythonDiskScanner\exports\`（数据目录）；
- `--quiet` 会把唯一告知文件去向的确认行 `📄 已导出目录占用报告: ...` 也吞掉——脚本用户拿到 0 字节线索。

**修复建议**：把 `_default_export_path` 移入 try 块（或单独捕获 OSError 给中文提示+退出码 1）；导出成功的目标路径行改走 stderr 或不受 `--quiet` 抑制；README 同步改口径。补一个"导出目录不可写"的单测。

## 二、P1 · 功能闭环建议

### 3. 缺少纯 CLI 的"建快照"入口
`--baseline` 可以消费快照，但创建快照只能靠 TUI（S 键/干净退出自动保存）或 Web 全量保存。定时任务/CI 场景无法纯命令行完成「今天扫一次存基线 → 明天 diff」闭环。建议增加 `--save-snapshot`（可与 `--snapshot-dir` 组合），让 README 的历史对比故事能脱离交互界面成立。

### 4. Web 服务重启丢失全部扫描成果
全量索引（BROWSE_INDEX）与最近结果只在进程内存。实测重启服务后 overview 变回"尚未扫描"、保存按钮灰掉，需要重扫两块盘（约 40s+15s）。而磁盘上明明有刚保存的 session 快照。建议：启动时从最近一份 session 快照**只读水合**概览与浏览（标注数据时间"来自 HH:MM 快照"），或把 BROWSE_INDEX 序列化缓存到数据目录。

### 5. 全量扫描期间浏览任意路径被一刀切 409
`app.py api_browse` 分支②：正在扫 C:\ 时，浏览 D:\ 下任意子目录也返回 409「全量扫描进行中」。其实此时 SDK 锁空闲（后台线程持有的是同一把锁，但排队即可）。建议：要么允许按需查询排队等待，要么文案给出预计剩余时间并在完成后自动刷新。

### 6. CLI Top-N 排行被同一条祖先链刷屏
实测 Top10 中 `.venv → .venv\Lib → …\site-packages → …\pip → …\_vendor` 一条链占 5 席，信息密度低。Web 端已有 leaf 口径，CLI 建议跟进：默认或可选 `--leaf-only` 只展示叶子目录（合计口径不变）。

### 7. 非交互模式缺文件级大头视图
目录聚合之外，"到底是哪几个大文件"是磁盘清理的第一问。TUI 内部已缓存每目录 Top50 文件却不对外透出。建议 `--top-files N`（屏幕报告）与导出可选文件明细。

### 8. TUI 大写 S 键位误触风险
`s`=下移、`W`=上移、但 `S`=保存快照、`H`=历史对比——大小写语义不对称（W 大写仍是移动，S 大写却是写盘）。CapsLock 开着按方向键会意外落盘。建议：保存类动作换键（如 F2/`A`）或加二次确认；至少在 help 文案里强调。

## 三、P2 · 打磨与一致性

9. **CSV 导出 Content-Type 双 charset**：实测响应头为 `text/csv; charset=utf-8-sig; charset=utf-8`（mimetype 与 Response charset 叠加），建议只保留一处。
10. **文档漂移**：
    - README 导出默认位置（见 P0-2）；
    - `session.py` 模块 docstring 写死"每次全量保存 = C、D 各一份"，实现已是按全量结果的根逐盘保存（`_save_fullscan_result`），注释应改；
    - 「已知边界」里的 P12·W3.3、D8 等内部工单编号对外部读者是噪音，建议收敛到 docs/ 内部文档。
11. **`--quiet` 语义再收窄**：错误与关键结果（导出路径、对比结论）建议始终输出（stderr），只静默过程日志。
12. **测试建议补三类用例**：① leaf_only 大数据量性能回归（对应 P0-1）；② 数据目录不可写时的导出/保存降级路径；③ Web 对比的 root 大小写混合基线（README 已声明 normcase 口径，但值得锁住）。
13. **open-path 未实测项**：`explorer /select` 定位失败静默的问题 README 已如实声明兜底方案，建议后续给接口加可观测回执（成功/降级原因），便于前端 toast 提示。

## 四、做得好的地方（保持）

- **健壮性设计**：临时文件+fsync+os.replace 原子写、.snapshot.lock 并发互斥、撤销保存带台账回滚（实测 undo 干净利落）、跨盘/异机基线双重拦截且逃生口三端齐全。
- **安全细节**：仅绑定 127.0.0.1、Host 白名单防 DNS rebinding、设置写入白名单并封死 everything_* 投毒链、DLL 仅采纳程序目录内路径。
- **工程质量**：260 项单测三轮全绿、ResourceWarning 门禁、golden/API 契约护栏、键位-帮助文案单一事实源（keyrouter）。
- **性能**：Everything 扫 C 盘 41 万记录约 40 秒；已扫描盘浏览即时（内存索引）；轻刷/深刷分级合理。
- **错误文案**：中文、具体、可行动（如 Session 0 会话错位的专门提示）。
