### 冲突9 替代护栏设计（受控修改三文件的前置条件）

1. **兼容性回归先行**：动手前先合入三类回归并纳入 419 基线——(a) 快照格式 golden 夹具（format v1 存量快照可被新代码读写）；(b) API 字段契约断言（12 条路由关键字段逐一断言）；(c) 聚合口径夹具（哨兵值/合计，即 W1.1/W1.2 验收夹具）。
2. **两条红线不变**：快照文件格式（format v1、头部字段、`{"p","s"}` 行格式）不变；已有 API 字段语义不破坏（只增不改不删，新增走 additive）。
3. **变更面收敛**：scan.py 仅限尺寸读取路径收口（read_result_size 主扫描/轻刷两处共用）；compare.py 仅限合计口径与 leaf_only 参数（缺省行为保持旧行为，Web 显式启用）；snapshots.py 仅限配额接线、陈旧锁检测、docstring；每项独立提交、可单独回滚。
4. **合并闸门**：每项合并前 `python -m unittest discover` 全绿；护栏测试任一变红即冻结该文件后续变更。

## 二、迭代目标与范围

**目标句**（沿用 PM §二唯一目标句）：让每个新用户在本版本上跑通「就绪 → 可信数字 → 定位大头 → 打开处理 → 存快照 → 次日一键对比」的完整闭环，全程看不到一个错误或看不懂的数字。

**In**：
- 批次一（发布门槛 P0）：哨兵值过滤、对比合计口径、Everything 引导包（自动拉起+错误映射+引导态+Session 0+N3）、行动闭环最小集（打开/复制+文件行修复）、TUI 崩溃修复、护栏回归先行；

- 批次三（P3 打磨/还账）：R-1 内存瘦身、概览自动刷新、空目录口径文档、徽章反馈与版本号铺垫、隔离数据目录破坏性流程验收。

**Out（不做，对齐 PM Non-goals，注明被推迟项去向）**

| 不做项 | 去向 |
|---|---|
| 删除/移动文件 | 永久 Non-goal |
| MFT 备用引擎 | backlog |
| 定时快照/自启/托盘 | backlog |
| 设置扩展（G-4 快照目录自定义等） | backlog（everything_* 因冲突1裁决长期不可从 Web 写入） |

| API/快照格式变更 | 红线不变（冲突9 护栏第 2 条） |
