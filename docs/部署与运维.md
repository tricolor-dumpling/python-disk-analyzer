## 1. 三种形态怎么跑

| 形态 | 启动命令 | 说明 |
|---|---|---|
| **Web（主形态）** | `python app.py` | 默认打开浏览器；`--no-browser` 不开、`--verbose` 打开 CLI 风格启动日志、`--debug-log` 保留 Werkzeug access log |
| **TUI** | `python main.py` | 无参数即进入交互界面 |
| **CLI** | `python main.py <TARGET> [--top N] [--quiet] [--export csv\|json] [--baseline PATH] ...` | 给了 `TARGET` 就走非交互 |

共同前提：本机装有 Everything（Web/TUI/CLI 都会尝试自动拉起），且 `everything-SDK/dll/` 下有匹配当前
Python 架构的 DLL。首次运行前 `pip install -r requirements.txt`（仅 Web 形态需要 `flask`）。

## 2. 端口与绑定

- **绑定地址固定 `127.0.0.1`**，不接受外部访问；`threaded=True`（前台浏览与后台扫描并发靠锁串行，不靠单线程）。
- **端口默认 5000**，且**没有命令行开关可改**（`run_server(port=5000, ...)`）；
  需要换端口只能改代码或做本机端口转发。
- 端口占用时有两种情形，行为不同：
  1. **已被本工具的另一实例占用** → 探测到 `/api/health` 返回 200，打印
     「端口 N 已被本工具实例占用，将打开已有实例页面」，然后**直接退出**（不 bind、不报错）；
  2. 被**其它程序**占用 → 探测失败（异常即视为无实例），继续 bind，由 Flask 抛错。

## 3. 多实例行为（防双实例探测）

探测实现：`app.py::_another_instance_running(port)` 向 `http://127.0.0.1:<port>/api/health` 发一次
**1 秒超时**的请求；**能取到 200 即认定已有本工具实例**，任何异常（连接拒绝/超时）都视为无实例。

| 你的意图 | 正确做法 | 说明 |
|---|---|---|
| 就用现在这个实例 | 直接访问打印出的 URL | 第二次 `python app.py` 会自行退出并把浏览器指过去 |
| 真的想再开一个 | 先关掉旧实例 | 端口写死 5000，两个实例无法共存 |
| 旧实例「看不见」但端口被占 | 用 `Get-NetTCPConnection -LocalPort 5000` 查占用进程 | 若是别的程序占用，属上面第 2 种情形 |

> 判定的副作用：健康检查**很慢或卡住**时（>1s），探测会误判为「无实例」，随后 bind 失败并抛错。
> 这不是数据损坏，重试即可。

## 4. 停服与数据一致性

- **退出时会协作取消后台扫描**：`atexit` 注册 `_shutdown_fullscan()` → `fullscan.cancel_scan(join_timeout=5)`，
  置位取消事件后**最多等 5 秒**；超时则放弃等待（**不硬杀线程**）。
- 因此「已完成的部分根保留、`error=None`、状态记 `cancelled`」；不会留下半写快照
  （快照是临时文件 + `os.replace` 原子替换，见 [`docs/架构决策记录.md`](架构决策记录.md) ADR-4）。
- 写入进行中强制关窗（任务管理器结束进程）也不会产生半截快照文件，最多丢失**本次未落盘**的进度。

## 5. ⚠️ 子进程防孤儿：三种形态并不一致

`env.init_windows_job_sandbox()` 建立的是 **Windows 作业对象**（`JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`）：
本进程退出时，被绑定进该作业的子进程会被内核一并终止，用于防「自动拉起的 Everything 变成孤儿」。

| 形态 | 是否初始化作业沙盒 | 后果 |
|---|---|---|
| CLI（非交互） | ✅ `cli.py` 在 `ensure_everything_running()` 前调用 | 退出时自动拉起的 Everything 一并结束 |
| TUI（交互） | ✅ 同上 | 同上 |
| **Web（`python app.py`）** | ❌ **当前未调用** | 若本次运行**自动拉起**了 Everything，退出服务后该进程**会继续运行** |

**运维口径**：Web 形态退出后发现 Everything 仍在跑，属**已知行为**而非故障——Everything 是常驻索引服务，
留着并不影响后续使用。若确实要一起结束，手动退出 Everything，或在启动前就让 Everything 处于运行状态
（这样程序不会去拉起它，也就没有孤儿可留）。

> 该差异已如实登记；如需统一，应在 `app.py` 的启动路径补 `init_windows_job_sandbox()`（属行为变更，
> 需同步 `tests/test_shutdown.py` 与本文）。

## 6. 数据目录与隔离

| 用途 | 位置 | 备注 |
|---|---|---|
| 运行时数据 | `%LOCALAPPDATA%\PythonDiskScanner\`（`snapshots/`、`exports/`、`config.json`、session 清单） | 可由 `--snapshot-dir` / `DSA_SNAPSHOT_DIR` 改快照位置；`DSA_NO_SNAPSHOT` 禁用快照落盘 |
| 破坏性验收的隔离根 | `D:\deepseek\dsa-isolated\<时间戳>` | 脚本重定向 `LOCALAPPDATA` 实现零代码改动隔离，带「仍指向真实目录就终止」的安全闸门；跑完 `-Cleanup` |
| 测试夹具 | `%TEMP%\pds_fixture_snapshots_<ts>` | 生成器内置守卫，拒绝写入真实数据目录 |

> 项目目录**不产生**运行数据（除首次默认模板 `config.json`）；`config.json` 实际读写走数据目录。

## 7. 常用运维命令

```powershell
# 启动（不开浏览器，适合后台/脚本）
python app.py --no-browser

# 排查端口占用
Get-NetTCPConnection -LocalPort 5000 -ErrorAction SilentlyContinue | Select-Object OwningProcess, State
Get-Process -Id <OwningProcess> | Select-Object ProcessName, Path

# 看 Everything 是否在跑、SDK 是否可解析
python -c "import env, sdk; print(env.is_everything_process_running()); print(sdk.resolve_everything_dll())"

# 破坏性流程干跑（不真改数据）
powershell -File scripts\dev\destructive_acceptance.ps1 -WhatIf
```

## 8. 发版交付校验清单

> ⛔ **触发条件（先看这条）**：本清单**只在项目负责人显性通知发版时**才执行（例如「发版 v2.2.0」）。
> 开发过程中**不得**自行改版本号、打 tag、建 Release 或宣告版本——见 [`README.md`](../README.md)「版本标记纪律」。

发版步骤的**唯一权威**是 [`AGENTS.md`](../AGENTS.md) 第 8 节；本节是把它变成**可勾选、可复核**的清单。
版本号唯一落点：`web/templates/index.html` 状态栏 `.statusbar-left`（形如 `v2.1.1 · R1 视觉版`）。

**发版前**

- [ ] **已收到项目负责人的显性发版通知**，且版本号以通知为准（不自行推断下一个版本号）
- [ ] `pytest tests -q` 全绿（含两套文档契约）

- [ ] 冒烟：浏览器打开 `tests/web/smoke.html`，标题为 `[suite=v2][PASS 23/23]`（**不要重复 open**）
- [ ] 本轮变更已按 `docs/开发规范.md` 第 3 节清单同步文档，且 `docs/CHANGELOG.md` 有对应条目
- [ ] 版本号已改并**单独提交**

**打包（结构要求）**

- [ ] 顶层单目录 `python-disk-analyzer-X.Y.Z/`，内含全部根 `*.py` + `web/` + `everything-SDK/dll/`

**发版后外部校验**（不看本地状态，只验远端）
