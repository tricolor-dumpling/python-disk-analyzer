## 一、全局执行纪律（每一阶段都必须遵守）

1. **五步流程**：每阶段按本手册给出的六节顺序执行，不得跳过测试与验收；未完成项如实记录，不伪造验收结果。
2. **合并闸门**：每项独立提交前必须通过
   - `python -m unittest discover -s tests` 全绿；
   - W1.0 完成后追加 `-W error::ResourceWarning` 卫生门禁；
   - 改动过 `web/static/js/app.js` 的，必须跑通 `tests/web/smoke.html` 全部四断言。
3. **受控修改护栏**（针对 scan.py / compare.py / snapshots.py）：先有护栏回归再动手；快照格式（format v1）与已有 API 字段语义两条红线不变，新增字段一律 additive；`(sizes, contents)` 二元组解包契约与 `save_snapshot -> Path|None` 返回契约冻结。
4. **提交规范**：一工作项一提交，message 格式 `P12a-W1.1: <摘要> (DEF-001)`；禁止跨工作项混合提交，保证可单独 revert。
5. **环境事实**：Windows · Python 3.11.8 · Flask 3.0.2 · Node v24（可用于 `node --test`，但 npm/pnpm/npx 不在 PATH，严禁引入需安装的依赖）；Web 服务地址 `http://127.0.0.1:5000`（仅绑定本机回环）。
6. **基线核定硬门槛**：W1.0 未完成（unittest 实际用例数未记录、护栏回归未合入）之前，**禁止修改 scan.py / compare.py / snapshots.py**。

### 1. 设计
```python
STALE_LOCK_TTL_SECONDS = 600
def _pid_alive(pid):
    if pid is None: return False
    if os.name != "nt": return True            # 无法判定→交 TTL 兜底
    h = ctypes.windll.kernel32.OpenProcess(0x1000, False, pid)  # QUERY_LIMITED_INFO
    if not h: return False                     # 打不开=已退出
    kernel32.CloseHandle(h); return True
def _is_stale(lock_path):
    pid = int(内容) 失败→None
    if pid is not None and _pid_alive(pid): return False   # 活进程优先于 TTL
    return time.time() - lock_path.stat().st_mtime > STALE_LOCK_TTL_SECONDS
```
_acquire_lock 的 FileExistsError 分支：_is_stale 成立 → unlink 后**重试 O_CREAT|O_EXCL 恰好一次**（偷锁仅一次，防双偷双写）；仍失败抛 SnapshotBusyError。

## 附录B · 隔离数据目录破坏性流程验收脚本大纲（W3.5 配套）

**环境变量重定向方案**：脚本开头 `$real="$env:LOCALAPPDATA"`，随即 `$env:LOCALAPPDATA="<隔离根>\home"`（PowerShell 5.1 语法，无 `&&`）；此后本进程及其全部子进程（`python app.py`、打包 exe、`python -c` 探针）继承该值，datadir.get_data_dir() 即解析到隔离根下的 PythonDiskScanner。第 0 步闸门：`python -c "import datadir;print(datadir.get_data_dir())"` 输出必须以隔离根开头且 ≠ `$real`，否则立即 `throw` 终止。

**脚本步骤序列**：
1. **save**：隔离环境下启动服务→触发全量扫描（小范围根）→完成点「保存快照」→断言快照目录生成 .gsz 与 session 清单文件；
2. **校验台账**：`session.list_sessions()` ≥1、台账内 roots/snapshot_path 与磁盘一致；
3. **undo**：调 POST /api/save/undo（危险确认由 API 层跳过，UI 双确认为 W2.6 范畴）→断言快照文件删除、**台账条目回滚**（W2.11 B-2）；
4. **指纹谓词恢复**：再次触发同根扫描完成→auto 保存不被旧指纹抑制（能再次生成新快照）；
5. **wipe 双确认**：POST /api/admin/wipe 先传错 confirm 得 400，再传「确认清空」得成功；
6. **清键集合与目录重建**：断言数据目录被清空后重建出空 `snapshots/`、`exports/`；浏览器 DevTools 执行 `Object.keys(localStorage)` 核对 W2.6 清键集合（`pds_handled_scan_version_v1`、lastBrowse 相关键、`pds_onboarding_dismissed_v1`）已消失；
