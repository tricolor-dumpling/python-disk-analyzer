## 一、项目现状速览（接手先读）

### 1.1 这是什么

Windows 本地磁盘空间分析工具。核心能力：借助 **Everything 索引**快速得到目录大小，用**矩形图/排行/表格/关系树**四种视图浏览，支持**全量扫描 → 快照保存 → 历史对比 → 趋势分析**，并有 CSV/JSON 导出。三端入口：CLI（`cli.py`）、TUI（`tui.py`）、Web（`app.py` + `web/`）。

**本计划只涉及 Web 端**（`app.py` + `web/`），CLI/TUI 仅在共享模块（`compare.py`、`snapshots.py`、`fullscan.py`）被间接影响时受约束。

### 1.2 技术栈与运行方式

```powershell
# 启动（默认打开浏览器；开发/验收一律用 --no-browser）
.venv\Scripts\python.exe app.py --no-browser            # http://127.0.0.1:5000/
.venv\Scripts\python.exe app.py --no-browser --debug-log # 需要看 access log 时
```

- 后端：Flask，仅监听 `127.0.0.1:5000`，`threaded=True`；重复启动会探测并复用已有实例（**验收前必须先确认端口是否已被旧实例占用**，否则测的是旧代码）。
- 前端：**无构建步骤**的原生 ESM（`web/static/js/app/**`）+ 单模板（`web/templates/index.html`）+ 两个 CSS（`web/static/css/tokens.css` 设计令牌、`web/static/css/style.css` 全部样式）。
- 数据目录：`%LOCALAPPDATA%\PythonDiskScanner`（`config.json` 配置、`ledger.json` 台账、`snapshots/` 快照、`session_*.json` 会话清单）。可用 `DSA_SNAPSHOT_DIR` 或 `LOCALAPPDATA` 重定向做隔离测试。

## 三、全局约束（红线）——违反即返工

### 3.1 视觉/界面类改动**必须**借助视觉验收

1. **任何改动 `web/` 下 CSS/模板/页面 JS 的工作，提交前必须提供真实浏览器截图证据**，不接受"代码看起来对"。
2. 截图必须来自**真实运行的服务**（`app.py --no-browser`，`http://127.0.0.1:5000/`），不接受静态 HTML 或桩 DOM 截图作为唯一证据（桩态探针可作为补充，但真机必须跑一遍）。
3. 截图必须覆盖**三档视口**：`1366×768`（紧凑档）、`1920×1080`（常规档）、`1440×900`（中间档）；涉及窄屏的改动另加 `900×700` 或 `357×651`。
4. 涉及布局的改动必须**同时给出量化测量**（`getBoundingClientRect` / `scrollWidth` vs `clientWidth` / 重叠检测），不能只给"看起来好了"。
5. 视觉判读必须走图像模型通道（见 4.4）；**主代理/开发者的人工判断不能单独作为 PASS 依据**，必须与像素/尺寸采样互证。
6. 截图与测量结果必须**入库归档**（放 `docs/问题核查资料_20260908/` 或对应阶段目录），不得只留在 `%TEMP%`。

### 3.2 动画/过渡类改动**必须**短间隔截图（本计划的核心纪律）

1. **禁止用终态断言验收动画。** 上一批 `2-2 视图残留` 连续 8 轮"未复现"的根因就是探针只在 700–800ms 后采样终态，120ms 的窗口早已关闭（`u50:232-242`、`u66:70-102`、`u56:123-133`）。**终态绿 ≠ 过程无异常。**
2. 动画验收必须使用**帧级采样**，三档工具按问题选择：

| 采样方式 | 节奏 | 适用 | 本机可用性 |
|---|---|---|---|
| 页内 `requestAnimationFrame` 记录器 | ≈16.7ms/帧 | DOM 状态类断言（`hidden`/`opacity`/`elementFromPoint`） | ✅ 已验证 |
| CDP `Page.startScreencast` | 实测 10–20ms/帧 | 像素类断言（扩散圆心、面积变化） | ✅ 已验证 |
| Playwright `page.screenshot()` | 实测 **~130ms/张** | **仅可作终态/粗粒度证据**，不能用于 120ms 级动画 | ✅ 但不够快 |

3. 采样窗口必须**从触发前开始、覆盖整个动画时长 + 200ms 收尾**，并断言"中间态全程满足约束"，而非只断言首末帧。
4. 每条动画断言必须写明**时间窗、采样节奏、判据、允许的例外**；例外必须在阶段交付报告里登记，不得默认放宽。
5. 涉及 `prefers-reduced-motion` 的动画，必须另跑一次 reduced 模式并断言"直切/静止"。

1. **additive only**：新增响应字段可以，删除/改名字段必须同步改全部调用方与契约测试。

### 4.2 三类截图节奏（**硬性**）

| 类别 | 节奏 | 帧数下限 | 用于 |

### 4.3 可脚本化判据（每阶段按需选用）

1. **DOM 可见性**：非活动视图在动画窗口内 `hidden` 恒真、`opacity` 恒为不可见值。
2. **命中测试**：`document.elementFromPoint(视区中心)` 在窗口内不得落在非活动视图内。
3. **像素面积**：对帧序列按亮度阈值分割新旧主题，旧主题像素数**单调递减**，相邻帧新主题面积跳变 ≤ 30% 视口面积，**末帧前旧主题像素为 0**。
4. **圆心拟合**：对扩散帧边界像素做最小二乘圆拟合，`|圆心 − 点击坐标| ≤ 4px`。
5. **布局溢出**：任意元素 `scrollWidth ≤ clientWidth + 1`（文本不被硬切）；兄弟元素 rect 无重叠（父子包含豁免，阈值 4px）。
6. **无内滚**：1366×768 下 `#side-rail` 的 `scrollHeight ≤ clientHeight + 1`（P6 红线，见 P3 约束）。
7. **控制台纪律**：`console.error` / `pageerror` 计数必须为 0。

## 七、P1 扫描完成自动保存与多次扫描策略（问题 1）

### 阶段信息

| 项 | 内容 |
|---|---|
| 覆盖问题 | 1（含用户追加的"多次全量扫描怎么办"） |
| 前置 | P0 |
| 触碰 | `fullscan.py`、`app.py`（`/api/save`、`/api/fullscan/*`、`/api/settings`）、`web/static/js/app/components/scan.js`、`components/settings.js`、`main.js`、`pages/workspace.js`（文案）、`snapshots.py`（**只读调用，不改语义**） |
| 产出 | 自动保存必达 + 跳过原因可见 + 多次扫描口径裁定 |

### 现象与证据

- **实测**：2026-09-08 20:08 全量扫描完成后，页面 toast 显示「全量扫描已完成，结果就绪，可保存快照」，`保存快照` 按钮保持可用 → 说明 `save_ready` 未被消费，**自动保存根本没被触发**。
- **实测**：用户真实数据目录 `%LOCALAPPDATA%\PythonDiskScanner\` 中，`session_..._000001.json`（10:47:20）为 `auto:false`（手动保存），`session_..._000002.json`（10:52:52）为 `auto:true`（自动保存成功）；Edge 的 localStorage 里 `pds_handled_scan_version_v1 = "2"`。

### 根因定位

1. **主因（跨进程闸门失效）**：`web/static/js/app/components/scan.js:470-473`
   ```js
   const version = Number(st.scan_version) || 0;
   if (handledScanVersion >= version) return;   // handledScanVersion 来自 localStorage
   ```
   而 `handledScanVersion` 由 `scan.js:30-38,43` 从 `localStorage["pds_handled_scan_version_v1"]` 读取；后端 `scan_version` 由 `fullscan.py:218`（初始 0）、`fullscan.py:286`（每次扫描 +1）维护，**每个服务进程从 0 重新计数**。
   → 服务重启后第一次扫描 `version=1`，而 localStorage 残留值 ≥1 → `maybePromptSave()` 直接 `return`：**不保存、不提示、不报错**，而 `save_ready` 仍为真 → 手动按钮可用 → 用户只能手动保存。这就是问题 1 的完整链条。
2. **次因 A（跳过被静默 + 手动入口被禁用）**：谓词/配额跳过走 HTTP 200（`app.py:495-517`），但 `app.py:549` 的 `fullscan.mark_saved()` 仍然消费 `save_ready`；前端只弹一条 info toast（`scan.js:500-502`、`labels.js:10-12`），并因 `save_ready=false` 把 `保存快照` 按钮**禁用**（`scan.js:444`）→ 出现"自动没存 + 手动也点不动"的死角。
3. **次因 B（子页面完成不触发）**：完成边沿的 DOM 守卫在 `maybePromptSave` 之前（`scan.js:291`）；用户在 `#/compare` 或 `#/snapshots` 时扫描完成 → 不保存，必须回工作台才补触发（`main.js:268`）；不回来就永远不保存。
4. **现状口径（多次扫描）**：前端设计是"每次完成都试一次"；后端 `app.py:487-488` 把 `tree_complete=auto`、`dirty=False` 写死放行，真正生效的是 `snapshots.py:340-350` 的「指纹变化 ∧ 当日未落」→ **同一根同一天只允许 1 份自动快照**；当天第二次扫描（即使内容已变）全盘 `skipped`，且会写 session 文件 → 反过来抑制下次冷启动的自动扫描（`main.js:307-319`）。

### 设计决策（**必须在 P1 开头冻结并写进交付报告**）

- **D1-1 自动保存归口**：推荐**后端归口**——全量扫描结果就绪时由后端读取 `config.auto_save` 触发一次 `_save_fullscan_result(auto=True)`，前端只负责展示结果。理由：消除"页面不在/刷新/重启"三类漏触发，且天然与 `scan_version` 生命周期一致。若选择保留前端触发，**必须**把闸门改为服务进程标识（`/api/fullscan/status` 增 additive `boot_id`），且必须覆盖子页面场景。
- **D1-2 多次扫描策略**：推荐**"每次扫描完成都尝试自动保存一次，由四原子谓词裁决"**，即不新增"跳过第二次"的规则；但**跳过必须可见可补救**：扫描卡内显示跳过原因 + `保存快照` 保持可用 + 提供「仍要保存（强制）」入口（走 `auto=false` 显式保存）。
- **D1-3 同日同根多份自动快照**：**默认不放宽**（维持每根每日 1 份自动 + 滚动保留 10 份）。若产品要求放宽，必须同步改 `snapshots.py` 谓词、ledger 字段、配额文档与 README，属独立变更集。
- **D1-4 设置项**：`auto_save` 键名与默认值（缺键视为 ON）**保持不变**；`/api/settings` 的 `ALLOWED_SETTING_KEYS` 不得扩大。

### 实现步骤

1. 写护栏测试（**先写测试再改代码**）：
   - 后端：扫描完成后自动保存恰一次；跳过时响应携带可见原因；跳过不消费 `save_ready`（或消费但保持手动入口可用）；服务重启后第一次扫描仍自动保存。

## 八、P2 工作台视图切换残留（问题 2）

### 阶段信息

| 项 | 内容 |
|---|---|
| 覆盖问题 | 2 |
| 前置 | P0 |
| 触碰 | `web/static/js/app/pages/workspace.js`、`web/static/js/app/viz/treemap.js`、`web/static/css/style.css`、新增 `scripts/dev/p02_view_frame_probe.mjs` |
| 产出 | 任意视图切换全程零残留（帧级证据）+ 探针纳入门禁 |

### 现象与证据

- **帧级实测（2026-09-08）**：页内 rAF 记录器（≈16.7ms/帧）对四组切换采样，`#treemap-wrap` 在**非矩形图→非矩形图**的切换中也被取消隐藏：

| 序列 | 采样帧数 | 违规帧数（`hidden=false`） | 首帧状态 |
|---|---:|---:|---|
| 排行→关系 | 63 | **9** | `opacity:1`，`elementFromPoint` → `treemap-canvas` |
| 关系→排行 | 68 | **8** | 同上 |
| 排行→表格 | 69 | **9** | 同上 |
| 矩形图→排行 | 69 | **12** | 同上 |

- 违规帧内 `#treemap-wrap` 的 `opacity` 从 `1` 渐降到 `0`（实测中间值 `0.382762`），即**整幅矩形图重新出现并淡出**，与用户"闪过"的描述一致。
- 视觉证据：`img/P2-视图残留帧_排行转关系.jpg`（排行行下方透出色块）。

### 根因定位

1. **主因 R1**：`workspace.js:562-589` 的 `crossfadeView(seq, showTreemap)` 把方向判成**"矩形图 vs 表格"二元**，而不是"上一视图 vs 下一视图"：
   - `:567-571` `outEl = showTreemap ? tableWrap : wrap;` → 目标非矩形图时，**矩形图被当成退场元素**；
   - `:571` `wrap.removeAttribute("hidden")` 强制取消隐藏；
   - `:582` `outEl.style.opacity = "1"` 把矩形图先拉回全不透明再淡出。
   → 排行→关系、排行→表格这类**与矩形图无关**的切换也会整幅重现 120ms（`tokens.css:9` `--dur-1:120ms` ≈ 7–12 帧）。
2. **形态 R2**：`style.css:135` 与 `style.css:745-749` 两个容器同为 `position:absolute;inset:0` 且**无 z-index**；`#treemap-wrap` 在 DOM 中靠后（`workspace.js:1179` 表格容器、`:1209` 矩形图容器）→ 叠加时**矩形图在上层**，所以表现为"矩形图盖在淡入的列表上"。
3. **半成品 R3**：`workspace.js:572-573` 加了 `.v-crossfade` 类，但 `style.css` 中**不存在该规则**（全库 grep 仅命中 JS）——层序/指针/裁剪从未定义。
4. **卫生 R4**：终态隐藏被推迟到两个 WAAPI 动画 `finished` 之后（`workspace.js:584-589`），连点会反复重启；`treemap.js:920-930` 的 `pause()` 只 `cancelAnim()`，**不 disconnect ResizeObserver、不重绘终帧、不清画布**，若在 600ms 入场动画途中切走，闪出的是残缺位图。
5. **为什么上一批 8 轮"未复现"**：探针只断言 700–800ms 后的终态；`u66` 连点序列结尾是 `"table","table"` 幂等点击（`u66:139`），在拍关键帧前已把终态拍平；且 u50/u66 的 view 关键帧**从未被判读**。→ **"未复现"是断言口径盲区。**

### 设计决策

- **D2-1**：保留"矩形图参与时"的 120ms 交叉淡化（这是设计意图），但**方向判定必须改为"上一视图 vs 下一视图"**。
- **D2-2**：补齐 `.v-crossfade` 的 CSS 语义（层序 + `pointer-events`），确保动画期间入向视图（不透明背景）在**上层**，且 120ms 内点击不会打到隐藏的矩形图。
- **D2-3**：`pause()` 必须成为"真暂停"：断重绘、收束终帧、隐藏态不再响应 hover 重绘。
- **D2-4**：**关闭依据只能是帧级断言**，终态断言不构成关闭依据（写入 README 与清单）。

### 实现步骤

1. 新增 `scripts/dev/p02_view_frame_probe.mjs`：把 P0 的 rAF 记录器正式化，覆盖 `treemap→ranking→table→relate→ranking→table→treemap` 全序列 + 30ms 连点变体，输出 `frames.json` + 每帧截图。
2. 修 R1：`setBrowseView` 里改为 `const treemapInvolved = prev === "treemap" || mode === "treemap";`，只有 `treemapInvolved && prev !== mode` 才走 `crossfadeView`，否则直接 `finishViewSwap`。
3. 修 R2/R3：补 `style.css` 的 `.v-crossfade` 规则（入向容器 `z-index` 高于退场容器、`pointer-events:none`），并核对与 `#browse-loading`（`style.css:726` `z-index:5`）、全屏态（`style.css:798-802`）的层序关系。
4. 修 R4：`treemap.pause()` 增加 `paused` 标志，`doResize()`/`highlightKey()` 在暂停时直接返回，并在暂停时 `drawFinalFrame()` 收束；`workspace.js` 列表 hover 联动前先判当前视图。
5. 回归既有探针：`u50`、`u56`、`u66` 的终态断言必须保持全绿；把 `u66` 结尾的 `"table","table"` 改为跨视图序列。

### 约束

### 现象与证据

- 代码定位：
  - `app.py:887`、`app.py:961` 写死 `leaf_only=True`；`app.py:891`、`app.py:969` 只回 `top_growth(report, 100)`；
  - `compare.py:130-168` `_merge` 无 depth、无 rollup；`compare.py:101-127` `_leaf_keys` 只回答"是不是叶子"；
  - `compare.py:142-159` 对两侧键并集**每键都产行**（`delta` 可为 0）；
  - `compare.py:251` `top_growth` 按**有符号 delta 降序** → 零行排在所有正增量之后、负增量之前；正增量 <100 条时零行补位，**零行 ≥100 条时负增量（可释放）被整段截断**；

  - 历史伏笔：`test-report/产品经理体验评审.md:55`、`test-report/用户实测迭代意见_20260826.md:71` 已提过"一条链占多行/建议按最深目录 rollup"。

### 设计决策

- **D4-1 深度聚合放在后端**（推荐）：在 `_merge` 排序/截断**之前**按路径前缀聚合到指定深度。理由：前端聚合只能处理"已被 top-100 截断"的叶子行，上层目录增量会被严重低估。
- **D4-2 参数语义**：`/api/compare` 新增可选 `depth`（int，≥1）。**不传 = 完全维持现状（叶子口径、逐字节同旧行为）**，保证向后兼容与既有测试不变。
- **D4-3 零增量处理**：后端在排序/截断前过滤 `delta == 0`；排序改为"按 |delta| 降序"以让正负增量都能进榜。**注意**：`top_growth` 被 CLI/TUI 共用（`cli.py:518`、`tui.py:593`），因此**新增参数**（如 `min_abs_delta` / `order_by`）而**不得改默认行为**。
- **D4-4 空态判据**：前端"无差异"必须基于**过滤后**的行集合，而非原始 `rows.length`。
- **D4-5 摘要口径**：摘要卡的"总变化/最大增长/可释放"必须基于**未截断的全量聚合行**（后端可 additive 返回 `rows_total`、`zero_count`、`max_growth`、`max_release`），避免与 `delta_total` 自相矛盾。
- **D4-6 下钻交互**：行点击 = 在对比页内**按该目录为新的根重新对比/聚合**（或跳到工作台浏览该路径），二者择一并记录；推荐"页内下钻 + 面包屑"以贴合用户"支持进入更深目录"的诉求。

1. 后端：
   - `compare.py:_merge` 增加 `depth=None` 与 `drop_zero=False` 参数；聚合复用 normcase 规范化（`_leaf_keys` 已有）；

3. 测试：
   - `tests/test_compare.py` 补 depth 聚合用例（多层、大小写、跨盘、空集、`depth` 大于实际层数）；
   - 补零增量过滤与排序用例；

## 十三、P7 主题扩散修复（问题 10）

### 阶段信息

| 项 | 内容 |
|---|---|
| 覆盖问题 | 10 |
| 前置 | P0 |
| 触碰 | `web/static/js/app/theme.js`、`components/settings.js`、`main.js`、`web/static/css/style.css`（如需）、`scripts/dev/u62_theme_vt_probe.mjs`、`u63_theme_coord_probe.mjs`、新增 `p07_theme_pixel_probe.mjs` |
| 产出 | 圆心=鼠标位置；无瞬间铺满帧；像素级判据入库 |

### 现象与证据

- **实测**：顶栏按钮路径的扩散**圆心正确**（见 `img/P10-主题扩散帧_顶栏.jpg`，圆形弧线中心在按钮位置）→ 说明"不从鼠标位置扩散"发生在**其它路径**。
- 代码定位：
  1. `theme.js:94` 只校验 `typeof ev.clientX === "number"`；`main.js:45` 绑的是 `click` → **键盘 Enter/Space 或 `el.click()` 产生 `clientX=clientY=0`**，被当作合法坐标，圆从**视口左上角**扩散；
  2. `main.js:245` 命令面板「切换主题」传 `null` → 走直切分支，**完全没有扩散**；
  3. `theme.js:104-106` 用视口空间（`clientX/clientY` + `window.innerWidth/innerHeight`），但 clip 作用于 `::view-transition-new(root)`（`theme.js:121-122`），**代码中无任何空间换算**（无 `getBoundingClientRect` / `scrollY`）；
  4. `theme.js:122` 的 WAAPI options **没有 `fill`** → 450ms 结束时 `clip-path` 计算值回到 `none`，**未被圆覆盖的像素在一帧内全部变新主题**——即 `theme.js:84` 自己命名的"一次性铺满帧"。几何上，顶部起点使底边在约 34% 时间被穿过、最远水平角要到约 92% 才覆盖，因此任何半径不足都**只在底部两角显现**，与用户"底部触底后两端瞬间完成"的描述吻合；
  5. `settings.js:197` 的 300ms TTL + `settings.js:226-233` 的 `pointFrom` 回退：慢点击/点在外边距/键盘激活时圆心退回**控件中心**。
- 探针盲区：`u62:115` 断言的 `documentElement.style.clipPath` **从未被写入**（`theme.js:114/127` 清的是它）→ 断言恒真；`u62:253` 是死分支；`u63:90-112` 只比对 keyframe 字符串，**测不到渲染圆心**。

### 设计决策

- **D7-1 坐标空间对齐**：用 clip 参考盒换算——`const b = documentElement.getBoundingClientRect(); x = ev.clientX - b.left; y = ev.clientY - b.top; W = b.width || documentElement.clientWidth; H = b.height || documentElement.clientHeight; maxR = Math.hypot(Math.max(x, W-x), Math.max(y, H-y)) * 1.02 + 16;`
- **D7-2 消除一帧铺满**：WAAPI options 加 `fill: "forwards"`，使动画结束后 clip 保持终帧；伪元素随转场销毁，不残留。
- **D7-3 伪坐标兜底**：`ev.detail === 0 && ev.clientX === 0 && ev.clientY === 0` 视为"无坐标" → 用触发元素的 `getBoundingClientRect()` 中心，或直切；`main.js:245` 传入面板项元素中心以恢复扩散。
- **D7-4 设置弹窗坐标**：去掉 300ms 时间 TTL，改为"下一次 `change` 消费 / 弹窗关闭时清空"；`pointerdown` 记录放宽到整个 `#setting-theme` 组。
- **D7-5 验收必须像素级**：圆心拟合 ≤4px、末帧前旧主题像素为 0、相邻帧新主题面积跳变 ≤30% 视口面积。

### 实现步骤

1. 新增 `scripts/dev/p07_theme_pixel_probe.mjs`：CDP screencast（10–20ms/帧）覆盖 ①顶栏 9 点；②设置弹窗选项中心与 +12px；③键盘激活；④命令面板；⑤滚动变体（scrollY=0/300/600，若页面可滚）；每组输出帧序列 + 圆心拟合 + 面积曲线。

| 全量扫描 | 通过 Everything SDK 遍历所有本地盘根，构建 `BROWSE_INDEX` | `fullscan.py` |
