## 1. 环境与工具链

### 1.1 控制台报 `'gbk' codec can't encode character '\U0001f9ed'`

- **原因**：Windows 默认代码页 GBK，控制台无法编码 emoji/中文。
- **怎么办**：入口最早处已调 `utils._reconfigure_std_streams()` 把 stdout/stderr 切 UTF-8；
  若你在**自写脚本**里看到此错，说明没有调用它或输出流被替换过。测试中遇到可直接断言源码/文案，
  不必依赖真实终端编码。

### 1.2 pwsh 命令直接失败：`SetNamedSecurityInfoW failed (Win32 5): grantWrite(<工作区>)`

- **原因**：DSH 文件沙盒无法为工作区目录授予写权限，**以工作区目录作为 `workdir` 的 pwsh 调用会整体失败**。
- **怎么办**：改用工作区外的目录作 `workdir`（如 `C:\Users\Laptop`），在命令内
  `Set-Location 'D:\deepseek\python-disk-analyzer'`。`read`/`write`/`edit`/`glob`/`grep` 工具不受影响。

### 1.3 `powershell` 语法报错（`&&`、`??`、三元）

- **原因**：本机是 Windows PowerShell **5.1**，不支持 PS7 语法。
- **怎么办**：用 `;` 或分行替代 `&&`；多行提交信息用 here-string `@'...'@ | git commit -F -`。

## 2. 扫描与 Everything

### 2.1 「Everything 未运行，请先启动」/「索引未就绪，请稍后重试」

- **看哪里**：`GET /api/health` 的 `ready`/`message`，或 TUI 横幅（模板 `E_NO_EVERYTHING_RUNNING`、
  `E_DB_NOT_READY`，见 `messages.BANNER_TEMPLATES`）。
- **原因**：① Everything 进程没启动；② 启动了但数据库仍在加载；③ SDK 报 IPC 错误（码 2）。
- **怎么办**：启动/重启 Everything；`env.ensure_everything_running()` 会自动拉起并等待 IPC。
  判定逻辑在 `sdk.is_everything_ready(query_ok, last_error, is_db_loaded)`——
  **数据库没加载完就不许阻塞扫描**，避免界面假死。

### 2.2 浏览器打不开 / 提示已有实例

- **原因**：`app.py` 在 bind 前会探测端口（`P12·W2.10 DEP-1` 防双实例）：能通则认为已有实例，直接复用其页面。
- **怎么办**：直接用提示的 URL；确需重启就先关掉旧实例。停服走**协作取消**（置位事件让扫描自行收尾），
  不硬杀线程——详见 `tests/test_shutdown.py`。

### 2.3 面板显示 `service_only`

- **含义**：Everything **全部运行在 Session 0**（服务会话），当前交互会话是 Session 1，两者 IPC 不通。
- **怎么办**：以普通桌面用户身份启动 Everything（不要只装服务），或按界面引导操作。
  判定见 `app.py` 健康分支，回归护栏 `tests/test_api_contract.py::test_service_only_flag`。

### 2.4 「未找到匹配当前 Python 架构的 Everything SDK DLL」

- **原因**：`sdk.resolve_everything_dll()` 按 **Python 进程指针宽度** 选 DLL，不是按操作系统架构。
  32 位 Python 会去找 `Everything32.dll`。
- **怎么办**：确认 `everything-SDK/dll/` 下有你所需架构的 DLL（仓库只登记 32/64 位两个文件，
  白名单见 `.gitignore`）；必要时在 `config.json` 写 `everything_dll` 覆盖（路径须在项目目录内才被接受）。

## 3. 快照与历史

### 3.1 快照页列表是空的，但磁盘上明明有会话

- **原因（最常见）**：会话被判为「无内容」或「夹具会话」而**不展示**。
  - 「无内容」= 全盘 `skipped`，或 0 字节；
  - 「夹具会话」= 保存根全部命中 `FIXTURE_ROOT_RE`（如 `C:\SDK1`、`D:\fixture...`）。
- **特别注意**：判定依赖 additive 字段 **`total_by_root`**——**在 `tests/web/smoke.html` 里造会话夹具时
  漏掉它，会话就会被判「空」而隐藏，A15/A17/A18/A20 连锁红**。
- **怎么办**：这是**展示层**过滤，后端契约不变（全盘 skipped 仍写清单，作审计轨迹，见
  `tests/test_stage_d.py`）。核对 `components/snapshot-view.js` 的 `splitSessions`。

### 3.2 合计大小明显偏大 / 提示「已知异常大小」

- **原因**：历史快照中存在大小 ≥ **16 TiB** 的「已知异常大小」行（旧版 Everything 的 `GetResultSize`
  语义问题，历史缺陷）。这些行会拉偏合计。
- **怎么办**：`legacy_unknown_rows`/`legacy_count` 是 additive 提示字段，界面会提示重扫重建基线。
  阈值三处同值（`scan`/`snapshots`/`compare` 的 `_LEGACY_SIZE_THRESHOLD` = `16 * 1024 ** 4`），
  **改动必须三处同步**，由测试强制。
- **完整处置流程**（三种计数口径的区别、要不要重建、重建步骤、常见误区）见
  [`docs/legacy 快照迁移指引.md`](legacy%20快照迁移指引.md)。

### 3.3 保存被跳过，界面提示「已自动保存(今日 1/1)」

- **原因**：自动保存受 `snapshots.should_auto_save` 四原子谓词与**日配额**约束
  （`MAX_BYTES_PER_DAY` = 102.4 MiB、`AUTO_MAX_PER_ROOT_PER_DAY` = 1）。
  auto 是**硬门槛**（超限直接跳过），explicit 保存只**软警告**但仍落盘。
- **怎么办**：属预期行为。回归护栏 `tests/test_budget.py`；`DSA_NO_SNAPSHOT=1` 可整体禁用快照落盘。

### 3.4 保存失败且提到「陈旧锁」

- **原因**：快照写入用 `O_CREAT|O_EXCL` 锁文件；进程崩溃会遗留锁。
  超过 `STALE_LOCK_TTL_SECONDS`（600s）且确认无活进程时才允许「偷锁」。
- **怎么办**：等 TTL 或确认无残留进程后重试。护栏 `tests/test_stale_lock.py`（死 PID/TTL/活进程/非法内容）。

## 4. 界面与前端

### 4.1 对比页折线点一下就没了

- **原因**：主基准读取口径错误——`<select multiple>` 的 `.value` **恒等于 DOM 里第一个 selected 项**，
  一旦用它回写就会把多选塌缩成单选。
- **怎么办**：主基准只能读 `#compare-baseline.dataset.base` 或 state；点选落地只走
  `pages/compare.js` 的 `pickBaselineFromTrend()`。护栏是 `tests/web/smoke.html` 的 **A22**
  （见 `AGENTS.md` 第 3 节第 18 条）。

### 4.2 改了 `web/templates/index.html` 刷新看不到效果

- **原因**：Jinja 在非 debug 模式**缓存编译后的模板**（静态 JS/CSS 反而用 `no-cache`，改完刷新即可）。
- **怎么办**：**重启** Flask 进程。

### 4.3 冒烟测试突然红了 / 标题写「壳未 boot」

- **原因**：用浏览器工具跑 `tests/web/smoke.html` 时**重复 open 页面**，会打断正在跑的套件。
- **怎么办**：**一次 open 等标题出结论**即可；标题 `[suite=v2][PASS 23/23]` 为绿，
  失败会写明编号（如 `[FAIL 3/23 · A18,A20,A22]`）。
- 另两条硬纪律见 `AGENTS.md` 第 7 节第 6 条（夹具必须照抄 `total_by_root`；断言前置自行建立、失败靠轮询）。

### 4.4 前端单测整目录跑失败，但单文件能过

- **原因**：DSH 沙盒下 `node --test scripts/dev/` 的多进程隔离会受限，产生
  `test at scripts\dev:1:1 'test failed'` 假红。
- **怎么办**：用单进程模式：
  `node --test-isolation=none --test "scripts/dev/*.test.mjs"`（应得 86 pass / 0 fail）。

### 4.5 pytest 报 `PermissionError`，临时目录创建后自己都访问不了

- **原因**：Python 3.13+ 在 Windows 上给 `tempfile.mkdtemp()` 设了仅属主可访问的 DACL，
  在沙盒环境下创建者自身随后也可能被拒。
- **怎么办**：`tests/__init__.py` 已内置兼容垫片（探测到问题就替换为无特殊 ACL 的等价实现），
  正常环境行为与标准库一致——**不要**在用例里自行绕过 `tempfile`。

## 5. 拿来即用的诊断命令

```powershell
# 健康与环境
.\.venv\Scripts\python.exe -c "import env, sdk; print(env.is_everything_process_running()); print(sdk.resolve_everything_dll())"

# 后端全量（含文档同步契约）
.\.venv\Scripts\python.exe -m pytest tests -q

# 只跑 API 契约（改路由后必跑）
.\.venv\Scripts\python.exe -m pytest tests/test_api_contract.py -q

# 前端纯 JS 单测（沙盒用单进程模式）
node --test-isolation=none --test "scripts/dev/*.test.mjs"

# 造离线快照夹具（默认写 %TEMP%，拒绝写真实数据目录）
node scripts/dev/fixture_snapshots.mjs

# 破坏性流程干跑（不真改数据）
powershell -File scripts\dev\destructive_acceptance.ps1 -WhatIf
```

排查产出的日志/截图/临时脚本**统一放 `tmp/`**（不入库，可随时整体删），见 [`tmp/README.md`](../tmp/README.md)。
