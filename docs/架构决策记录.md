# 架构决策记录（ADR）

> **一句话职责**：回答「**为什么这么设计**」。回答方式是按**主题**列出会影响后续改动的决策与其代价。
> 不回答「怎么用」（见 [`README.md`](../README.md)）、不回答「不能违反什么」（见 [`AGENTS.md`](../AGENTS.md)）。

| 属性 | 值 |
|---|---|
| 权威性 | 决策**理由**的权威。红线条目本身仍以 `AGENTS.md` 为准 |
| 权威来源 | 源码注释（`P12·W1.x` 等阶段标记）+ 对应测试；本文只做**提炼与索引**，不复制代码逻辑 |
| 更新触发 | 推翻或修订既有决策时（**不是**每次改动都要动它）；新决策若「不知道就会做错」才登记 |
| 唯一性声明 | 本文独占「决策理由与代价」；**不重复**写红线清单（`AGENTS.md`）、字段契约（`docs/API 契约.md`）、文件职责（`README.md`） |

**为什么需要这份文档**：这些决策的原始理由此前只散落在源码的阶段标记注释里（如 `P12·W1.1`、`阶段B（B-7）`），
新人读代码只能看到「这样做」，看不到「为什么不能那样做」，于是容易在想优化时把约束拆掉。
本文按主题把理由固定下来；**只登记有代价的决策**，不复述显然的做法。

---

## ADR-1 用 Everything SDK 做扫描引擎，代价是「全局串行化」

- **决策**：以本机 Everything 的索引（经 SDK DLL IPC）为唯一数据源，不自己遍历文件系统。
- **理由**：毫秒级全盘扫描是产品核心体验；自建递归遍历在 NTFS 大盘上无法做到。
- **代价（必须接受）**：SDK 调用**不可并发重入**——所有触碰 DLL 的路径（主扫描 / 轻刷 / 深刷 /
  指纹探测 / 健康探测 / 前台浏览）必须串行，于是有了 ADR-2 的全局锁。
- **另一代价**：数据新鲜度依赖 Everything 索引状态——「索引未就绪」时**不许阻塞扫描**
  （`sdk.is_everything_ready` 会先看 `Everything_IsDBLoaded`），否则界面假死。
- **索引位置**：`sdk.py`（DLL 选择/签名/IPC 健康）、`scan.py`、`env.py`；护栏 `tests/test_sdk.py`。

## ADR-2 全局扫描锁（单例）——不是性能优化，是正确性要求

- **决策**：`scan.SCAN_LOCK` 是唯一持锁实体；`fullscan.GLOBAL_SCAN_LOCK` 只是**同一把锁的别名**。
- **理由**：SDK 并发调用会 DLL 重入崩溃/串数据；前台浏览与后台全量必须互斥。
- **代价**：吞吐被限制为串行；拿不到锁的路径**必须立刻返回忙**（非阻塞 acquire → `409` / busy 形态），
  **不允许排队挂死**请求线程。
- **易错点**：新增任何 DLL 调用路径都要先确认走锁；锁被占时给「忙」而不是「等」。
- **索引位置**：`scan.py`（含锁持有者登记，供诊断）、`app.py`（409/busy）；护栏 `tests/test_busy.py`。

## ADR-3 协作取消，绝不硬杀线程

- **决策**：停止与看门狗只**置位 `threading.Event`**（`fullscan.CANCEL_EVENT` / `USER_STOP_EVENT`），
  由扫描循环周期性检查并抛 `ScanCancelledError` 自行收尾。
- **理由**：硬杀线程会在持有锁/半写文件/半构建索引时留下不一致状态；协作取消能保证「已完成的部分保留、错误为零」。
- **代价**：停止不是瞬时的（要等循环到检查点）；看门狗只能靠超时判定（单盘 15 分钟无行更新）。
- **易错点**：不要为了「停得干脆」改成 kill/terminate；取消不算失败（`error=None`，状态记 `cancelled`）。
- **索引位置**：`fullscan.py`、`scan.py`；护栏 `tests/test_shutdown.py`。

## ADR-4 快照写入：原子替换 + 独占锁文件 + 日配额

- **决策**：临时文件 + `os.replace` 原子替换；并发写用 `O_CREAT|O_EXCL` 锁文件互斥；
  自动保存额外受**日配额**与**四个原子谓词**约束。
- **理由**：
  - 原子替换 → 崩溃/断电只会留下「旧版本」或「新版本」，绝不产生半截快照；
  - 独占锁文件 → 多写者串行，冲突抛 `SnapshotBusyError` 而不是交叉写坏；
  - 崩溃会遗留锁文件，因此必须能判定**陈旧锁**（`STALE_LOCK_TTL_SECONDS=600` + 活进程校验）才允许偷锁。
- **代价**：写入路径变长；出现「陈旧锁」类报错时用户需要等 TTL 或确认无残留进程。
- **易错点**：不要绕过这些护栏（见 `AGENTS.md` 第 3.6 条）。
- **索引位置**：`snapshots.py`；护栏 `tests/test_stale_lock.py`、`tests/test_snapshot_golden.py`。

## ADR-5 自动保存是「四原子谓词」而非定时器

- **决策**：自动保存仅在 **完整树 ∧ 非脏 ∧ 指纹变 ∧ 当日该根未自动落** 四条同时成立时触发；
  并叠加按字节记账的日配额。
- **理由**：快照的价值在「可比对的时间点」。定时保存会产生大量无差别副本，既占空间又让历史列表失去意义；
  用「指纹是否变化」判定才符合「有变化才值得记一笔」。
- **代价**：用户长时间不变动数据时不会自动产生快照（这是**有意行为**）；
  需要留痕时用显式保存（explicit，只软警告、不受硬门槛阻挡）。
- **易错点**：`DSA_NO_SNAPSHOT` 禁用快照时，自动保存必须**一并失效**。
- **索引位置**：`snapshots.should_auto_save` / 台账 `ledger.json`；护栏 `tests/test_budget.py`、`tests/test_stage_p1.py`。

## ADR-6 依赖方向强制无环 + 可变全局走模块属性 + `main.py` 兼容层

- **决策**：模块按层依赖、禁止反向 import；跨模块可变全局一律 `import x; x.名字 = ...` 读写；
  `main.py` 保留为一个**兼容层**，用 `_LIVE_FORWARD` 动态转发旧顶层名。
- **理由**：
  - 无环 → 任一模块可独立测试与推理；
  - 模块属性读写 → `from x import 名字` 会在导入时**拷走值**，之后再赋值就断掉共享（是静默 bug）；
  - 兼容层 → 历史上 `main.py` 是巨型单文件，拆分后仍需保住外部（脚本/测试/用户）以 `main.<名字>` 访问的路径。
- **代价**：新增被外部使用的顶层 API 时要在 `_LIVE_FORWARD` 登记（漏登记 = 补丁失效，很难查）。
- **易错点**：叶子层（`datadir`/`exceptions`/`utils`）**不许** import 项目内模块。
- **索引位置**：`main.py`（`_LIVE_FORWARD`）；护栏 `tests/test_api_contract.py` 等对命名空间的打桩依赖。

## ADR-7 前端零构建：原生 ES Module 直出，模板缓存靠重启

- **决策**：`web/static/js/app/` 是原生 ES Module，由 Flask 静态路由直出，没有打包/转译步骤。
- **理由**：本工具是**本机单用户**应用，不需要代码分割、CDN 缓存或浏览器兼容兜底；
  引入构建链会让「改一行刷新即生效」退化成「装依赖 + 构建 + 排错」。
- **代价**：
  - 资源请求数多（本地可忽略）；静态资源用 `no-cache` 触发条件请求；
  - **`web/templates/index.html` 改动需重启 Flask**（Jinja 非 debug 模式缓存编译模板），
    而静态 JS/CSS 不缓存、刷新即可 —— 这个不对称是高频踩坑点。
- **索引位置**：`web/templates/index.html`、`app.py`（`_static_no_cache`）；纯函数单测在 `scripts/dev/*.test.mjs`。

## ADR-8 UI 偏好与后端配置分家（单一 localStorage 文档）

- **决策**：界面「使用习惯」类偏好统一走 `prefs.js` 的 `PREF_REGISTRY` + 单一 `localStorage` 文档 `pds_prefs_v1`；
  后端 `config.json` 只保留白名单三键 `auto_save`/`last_roots`/`theme`。
- **理由**：两类数据的**所有者不同**——UI 偏好属于「这台机器的这个浏览器」，后端配置属于「这台机器」。
  混在一起会导致：清空数据目录把界面偏好一并抹掉、多浏览器互相覆盖、以及设置接口变成任意键写入面（投毒风险）。
- **代价**：同名前缀的两套配置需要各自维护；新增设置项必须挂到设置弹窗的某个分页。
- **易错点**：禁止在页面里直接 `localStorage.setItem` 散键；清空数据目录**不会**清偏好。
- **索引位置**：`web/static/js/app/prefs.js`、`app.py` 的 `ALLOWED_SETTING_KEYS`；护栏 `tests/test_security.py`。

## ADR-9 「展示层过滤」不改变后端契约（快照列表只看有内容的会话）

- **决策**：快照列表只展示「有内容且非夹具」的会话（`meaningful`），空会话与夹具会话在**展示层**分组隐藏；
  后端**照旧**为全盘 skipped 的保存写清单。
- **理由**：后端清单是**审计轨迹**（那次保存确实发生过、哪些盘被跳过），删掉就失去可追溯性；
  而列表是给人看的，塞满零字节会话会让真正有用的历史不可见。
- **代价**：出现「磁盘上明明有会话，界面却不显示」的合理困惑——因此需要在界面给出「已隐藏 N 个空会话」
  这类说明，并保证判定依赖 additive 字段 `total_by_root`。
- **易错点**：造测试夹具时必须照抄后端真实载荷（含 `total_by_root`），否则会话被判空、连锁红。
- **索引位置**：`components/snapshot-view.js`（`splitSessions`）；护栏 `tests/test_stage_d.py`、`tests/web/smoke.html`。

## 维护约定

- **新增 ADR 的门槛**：该决策「不知道就会做错」才登记；显然的做法、纯实现细节不写。
- **修订**：决策被推翻时**改这一条**并写明新理由与代价，不要保留「已废弃」段落（历史走 `git log`）。
- **与红线的关系**：ADR 讲「为什么」，`AGENTS.md` 第 3 节讲「不许违反」。两者**只允许互相引用**，禁止复述。
- 本文受 `tests/test_docs_consistency.py` 的引用完整性检查约束（引用的路径必须存在）。
