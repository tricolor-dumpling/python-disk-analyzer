## 三、建议测试脚本/夹具（后续实施）

### A. 对比与趋势

构造同根快照时间点：当前、23 小时前、25 小时前、8 天前；另造跨盘基线。验证：

- 对比页 loading 必须转成功/错误/扫描中状态；
- 较昨日只命中 24 小时内；较上周只命中 `(24h, 7d]`；
- 跨盘选择要有明确提示；
- 无快照/损坏快照不能无限 loading。

### B. 二次扫描和停止

采样状态序列：`idle → running → completed/aborted/error`，分别测试完成后重扫、保存后重扫、第一次中止后重扫、连续点击启动。重点字段：`running`、`scan_version`、`roots_done`、`result_ready`、`save_ready`、`stop_requested`、`stop_reason`。

### C. 视图与动画

数据加载后在 0ms、100ms、500ms、动画结束四个时点截图：矩形图→排行→表格→矩形图；同时记录两个容器 hidden/class、canvas 数量、动画数量。主题按钮和设置选项分别从中心/边缘点击，桌面/窄屏/Edge/reduced-motion 各跑一遍。

### D. 快照安全操作

必须使用临时 `LOCALAPPDATA`/`DSA_SNAPSHOT_DIR` 或 mock 数据目录。删除测试应覆盖：单盘、整会话、已跳过根、路径越界、文件不存在、删除失败、台账恢复、清单原子写。

### E. 导出

覆盖无结果、全量完成、多盘指定 root、空结果、未知大小、CSV BOM/转义、JSON UTF-8、Content-Disposition 和命令面板入口。原错误 JSON 只应在无可导出结果等保护场景出现。

## 五、测试环境注意事项

- 使用正式 `run_server()` 与直接 `Flask test_client` 分开记录；后者可能绕过 stdout/stderr UTF-8 重配置并触发 GBK emoji 问题。
- 启动前记录并确认旧端口实例，禁止把旧实例响应当作新代码验证。
- Python 测试基线当前为 266；动效 Node 测试为 25；历史报告中的 419 仅作历史参考。
- 真实 Everything 扫描、停止、保存和删除必须在隔离数据目录中执行。

## 六、修改前禁止事项

1. 不要把“已有 API/按钮”直接当成“用户问题已解决”，必须完成对应场景回归。
2. 不要在真实快照目录直接测试删除/清空/撤销。
3. 不要仅通过删除 loading 文案掩盖对比、扫描或网络未收敛。
4. 不要通过字段缺失推断缓存来源；来源应由后端明确返回。
5. 不要为满足自动扫描而删除所有手动恢复入口，除非失败与停止流程已有可用替代方案。
