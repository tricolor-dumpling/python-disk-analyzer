## D1 快照删除粒度 —— ✅ 已裁定（单盘为主 + 整会话）

**裁定**：快照删除同时支持两种粒度，**单盘为主**：
- 会话列表每行提供「删除整会话」；
- 会话内盘条目提供「删除该盘快照」（主入口，贴近问题 3「管理快照处删除指定快照」）。

**理由**：
1. 用户诉求（问题 3）是清理「指定的」陈旧快照——多数场景是某个盘的旧快照，而非整份会话；单盘粒度是主诉求。
2. 整会话删除与「撤销最近保存」（`/api/save/undo`，仅最近一次）语义不重叠：撤销是最近一次全量保存的事务回滚（含台账），删除整会话是任意历史会话的清理；保留两者功能闭环。
3. 现有数据结构已支持双粒度：`session_*.json` 清单（session.py）按会话聚合、每会话 `roots` 字段按盘列出 `snapshot_path`；`snapshots.py` 滚动保留（KEEP_EXPLICIT/KEEP_AUTO）按文件维度，删除按盘 = 删单文件 + 回写清单/台账。

**影响**：
- 后端（阶段 C）：新增删除接口（additive，不动 13 个既有接口语义）。定位参数二选一：`session_id`（整会话）或 `session_id + root`（单盘）。需路径边界校验（沿用 W2.11/SEC-4 `resolve().relative_to(snapshots_root)`）、幂等（文件缺失静默成功）、台账/清单一致性（删除单盘后清单 `roots` 移除该盘；盘删空后清单本身是否保留待实现期定稿）、并发锁（沿用 `.snapshot.lock` 串行，**不触碰 P-1/P13 禁碰纪律**）。
- 前端（阶段 C）：快照页列表加删除按钮 + 确认弹窗（沿用红线 #9 弹窗栈）；空态/失败 toast。
- 测试（阶段 C）：单盘/整会话/已跳过根/越界/文件缺失/删除失败/台账恢复/幂等（隔离目录，禁真实 %LOCALAPPDATA%）。

## D2 自动扫描方案 —— ✅ 已裁定（方案 A：sessionStorage 一次性标记 + 当日会话判断）

**裁定**：采用方案 A——
- **触发**：打开页面时若满足「本会话未自动扫描过」（`sessionStorage` 键 `pds_auto_scan_v1` 缺失）且「当日未自动扫描过」（`localStorage` 或后端台账当日判断）→ 自动 `POST /api/fullscan/start`，成功后写 `sessionStorage` 标记；
- **防刷新重复**：`sessionStorage` 键 + 当日会话判断（刷新不重复、新标签页会话独立重判、当日多次打开不重复）；
- **自动保存**：扫描完成后自动 `POST /api/save {auto:true}`（沿用现有自动保存谓词 `should_auto_save` 四原子）；保存失败/被谓词拒绝 → 出恢复入口（手动「保存快照」按钮与说明）；
- **保留手动入口**：本轮不删除任何按钮（「扫描完成态再评估删除」，避免失败/停止后无恢复入口）。

**理由**：
1. 问题 5 原文「打开即全量扫描、扫描完自动保存、按钮可移掉」的诉求核心是「打开即扫 + 自动保存」；方案 A 以最小风险满足，同时保留失败/停止恢复能力（与《复现与修改定位清单》§六-5 红线一致：不得为满足自动扫描删除所有手动恢复入口）。
2. `sessionStorage` 一次性标记天然防「刷新重复启动」（问题 7/13 的二次扫描冲突风险）；当日判断防「当日多次打开反复全扫」（Everything 分钟级成本，G8 busy 窗口常态）。
3. 后端零改动：`/api/fullscan/start`、`/api/save`、自动保存谓词均已存在（app.py:366、512；snapshots.should_auto_save）。

**影响**：
- 前端（阶段 D）：启动条件/一次性键/失败恢复表；`sessionStorage` 键名 `pds_auto_scan_v1`（与既有 `pds_*` 键命名一致）；恢复入口文案表（未就绪/单盘/多盘/重复打开/完成/保存失败/中止/重扫）。
- 测试（阶段 D）：冷启动/刷新/未就绪/单盘/多盘/重复打开/完成/保存失败/中止/重扫；**恰一次**断言（Network 计数）；三视口截图。
- 验收：自动模式最多启动+保存一次；失败有恢复入口；三视口无重叠。

## D3 「关系目录」定义 —— ✅ 已裁定（父子层级树）

**裁定**：「关系目录」= **父子层级树**（以当前路径为根的目录层级结构，直观展示目录之间的大小占比与层级关系）。

**理由**：
1. 问题 8「没有关系目录的功能」在现有产品语境（磁盘空间分析）下最自然的解读是「目录层级关系」——用户想看到某目录下有哪些子目录、各占多大，而非符号链接/引用关系（Everything 数据源不提供链接元数据，成本高且不符现状）。
2. 父子层级树可**零新后端**实现：`/api/browse` 返回的 `directories`（含 `path/is_dir/size`）天然是父→子结构，前端递归渲染即得；对比页/快照页已有同一数据结构。
3. 阶段计划 R4 对应问题 2/8/12 一并处理（视图残留 + 关系目录 + 排行表格差异），父子层级树与「矩形图→排行→表格」三视图同属浏览视图体系，交互一致。

**影响**：
- 前端（阶段 C/E）：新增「关系目录」视图（树形/嵌套列表，可展开折叠；复用 browse 数据 + 现有三视图框架）；键盘可达（方向键/Enter 沿用 U4.1 矩阵）；窄屏适配。
- 测试（阶段 E）：造 8 层目录夹具；桌面/窄屏截图；键盘可达；与排行/表格差异对照。
- 不做：符号链接/junction/硬链接关系（登记为不在范围；若后续产品要求再评估 Everything 元数据能力）。

## D4 状态栏去留 —— ✅ 已裁定（32px 壳精简为「版本号 + 已选 N 项」）

**裁定**：保留 32px 状态栏壳，**删除固定说明文案**（数据保存路径 / Everything 驱动 / 本地监听地址），精简为「版本号 + 已选 N 项」；信息迁入设置弹窗与健康徽章 popover（信息不丢失）。

**理由**：
1. 问题 19 明确「希望删掉」固定信息（截图 7 = 底部状态栏 `index.html:112-118`：`数据保存在 %LOCALAPPDATA%\PythonDiskScanner（快照、清单与配置）· v2.0.0` / `Everything 驱动 · 本地服务仅监听 127.0.0.1`）。
2. 这些信息并非每屏必需：数据目录在设置弹窗已显示（`setting-data-dir`）；Everything 驱动/监听地址在健康徽章 popover 已显示（`popover-health`/`popover-health-dll`）。状态栏保留它们属于信息冗余。
3. 状态栏壳必须保留：`statusbar-selected`（「已选 N 项」）由 list.js 多选驱动（G3 核销语义），版本号是发版可追溯性信息；两者有功能/运维价值。

**影响**：
- 前端（阶段 E）：`index.html` 状态栏左右文案删除，保留 `<span id="statusbar-selected">` 与版本号（版本号来源待定：静态文案 vs 读后端版本字段，实现期定稿）；CSS 高度预算 32px 不变（F22）。
- 测试（阶段 E）：设置弹窗/健康徽章信息存在性断言（信息不丢）；状态栏快照前后对照；smoke 断言面（若 smoke 断言依赖状态栏文案，按「既有 ID 与 smoke 断言面不变」原则检查——smoke 依赖的是 id 不是文案，确认无文案断言）。

## D5 C 盘显示口径 —— ✅ 已定稿（逻辑尺寸为主 + UI 全处标注口径；用户授权「按最好的表现形式」）

**裁定**（用户 2026-09-02 会话授权「按照最好的表现形式来」，执行代理按最优方案定稿并登记）：
- **默认口径 = 逻辑尺寸（已占用逻辑字节）**：存储概览/扫描结果/对比报告显示**已使用逻辑尺寸**，与 Everything SDK 直读/资源管理器「已使用」一致；
- **UI 全处标注口径**：概览卡/环图 tooltip 与设置弹窗数据目录区标注「逻辑尺寸，未计硬链接重叠」；
- **不把 21.99% 偏差当 bug 修**：P12c 验收记录已归因「C 盘聚合口径偏差 ~22% vs 资源管理器 = 硬链接/逻辑尺寸固有差异」（docs/exec/P12c-W3.5-破坏性流程验收记录.md 挂账项）；本次定稿为**设计事实**而非缺陷；
- **分配尺寸（NTFS allocated）列为不在范围**：Everything SDK 不提供该元数据，自算/换数据源成本高且不在现状 API 之内；如产品要求新增口径再排期。

**理由**：
1. 现状数据源（Everything SDK）只提供逻辑尺寸；分配尺寸需另造数据通道，违背「既有接口一律 additive、最小改动」红线。
2. 标注口径是「表现最好」的关键：用户看到 21.99% 偏差会误以为 bug，标注「逻辑尺寸，未计硬链接重叠」即可消除误解，成本最低。
3. 与 D4 联动：删除状态栏冗余信息后，口径说明在概览卡 tooltip/设置弹窗出现，位置合理。

**影响**：
- 前端（阶段 E）：概览卡/环图 tooltip 文案 + 设置弹窗说明；不改任何后端计算。
- 测试（阶段 E）：tooltip 文案存在性断言；与资源管理器对照数值记录（偏差范围说明）。
- 文档：README 存储口径段更新（阶段 F 发布时）；《问题逐项核查报告_待修复.md》问题 5 归因段引用本文档。
