### 1.1 裁定与偏差记录

| # | 事项 | 处置 |
|---|---|---|
| 1 | `scripts/dev/_harness.mjs` 不在 P7 授权清单 | `screencast()` 增 `maxWidth/maxHeight`（**additive，不传时行为逐字不变**）：全尺寸 JPEG 采幅实测只有 ~10–15fps，450ms 动画被采成 2–3 帧 → 「相邻帧跳变」判据被采样粗糙放大成假违规；0.5× 采幅后帧间隔中位 **16ms**（实测 18 例全部 ≤17ms） |
| 2 | 命令面板路径的圆心**不可像素拟合** | 该路径执行时 `closePalette()` 与主题切换发生在**同一转场内** → 掩膜 = 圆 ∩（主题变化 ∪ 遮罩消失），边界非圆（实测同帧拟合样本 0–2、y 分量偏 30–37px、x 分量稳）。改用**可假**的等效判据：存在渐进扩散（`progressFrames ≥3`，直切时为 0）+ 若有拟合则 x 分量 ≤6px；并把该偏差如实写入证据 |
| 3 | 「末帧前旧主题像素为 0」的字面理解 | 逐帧看：动画进行中未覆盖区**本应**仍是旧主题，故按可判定形式落地为 ③「**末帧**旧主题像素 ≈0（≤5% 跨编码噪声底，实测 2–4%）+ 动画确实推进（≥3 中间帧）+ 无在跑 VT 动画/clip 残留」。真实铺满会留 30–100% 旧像素，二者量级相差一个数量级 |
| 4 | `fill:"forwards"` 的副作用 | 填充态动画对象会留在 `document.getAnimations()`（u62「无 VT 动画堆积」断言由 46/46 掉到 9/46）。修法：`vt.finished` 后 `anim.cancel()` —— 此刻伪元素已随转场销毁，取消不影响渲染，但清掉填充态；u62 断言面**判据不放宽**（仍要求 `vtAnimations === 0`） |
| 5 | u62 的两处盲区（提示词 §2.1） | ① `documentElement.style.clipPath` 从未被写入 → 断言恒真；② `if (!clean.clipPath === "")` 是 `boolean === ""` 恒 false → 终态帧**永不截图**（死分支）。修法：补**伪元素**计算 `clipPath` 观测量 + 只统计 `playState==="running"` 的 VT 动画 + 死分支改为 `!== ""` |
| 6 | `lastThemePointer` 的安全性 | 去掉 300ms TTL 后可能出现陈旧坐标复用 → 增「组外 `pointerdown` 立即清空」（捕获阶段，先于其它处理器），安全性不降级 |

### 3.3 采样与判据可信度（实测）

- 帧数：18 例合计 **584 帧**（min 30 / 中位 33 / max 34 帧/例）；帧间隔中位 **16–17ms**（0.5× 采幅，683×384 JPEG）。
- 覆盖曲线判据：`floodFrame`（<70% → ≥95% 单帧跳变）为 0；大跳变（Δ≥30%）落点均 <90%（中段 ease-out 自然斜率），按 D7-2 语义记录不判违规。
- 圆心算法：2×2 块均值掩膜（抑制 PNG/JPEG 跨编码差）+ 形态学去麻点 + RANSAC 圆（900 次采样、内点 1.5 块）+ Kasa 复拟合 + 弧跨度/残差闸门；备用「早期小面积质心」。
