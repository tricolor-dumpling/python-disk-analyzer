## 一、任务与根因

**问题 4（右栏排版与自适应）** — 已量化实测：
- `.side-rail{width:300px;flex:none}` 在 1024/1366/1440/1920 **四视口恒为 300px**，主列越宽右栏相对越窄。
- 扫描态注入真实文案后：`#fullscan-status` 高 **298px**、`#fullscan-status-text` 被压成 **30px 宽**（每行 1–2 字竖排）、`#scan-eta` 右缘越过 rail 右缘 **100px** 被 `overflow-x:hidden` 裁掉。
- 图例：`已使用40.04 GB35.3%` 在 1920 下 `.donut-legend-value` `scrollWidth 111 vs clientWidth 92`（溢出 19px）；紧凑档 `148 vs 180` **反向**（溢出 32px）→ `.donut-legend-value` 只有 `white-space:nowrap`，**无 overflow/ellipsis**。
- `.overview-actions` **无任何 base CSS 规则**（仅 <900px 分支）→ 三按钮在 130–204px 内换行竖排；卡标题「存储概览」在 1366×768 竖排成「存储概 / 览」。
- 右栏满态 `scrollHeight/clientHeight = 948/656`（1366×768）→ 内滚 292px。
- 跨尺寸差异来源仅两个媒体查询：`@media (max-height:820px)`（紧凑档）与 `@media (max-width:900px)`（右栏全宽）。**无 1366/1920 宽度断点，无容器查询。**

**问题 3（删除密度开关）** — 代码定位：
- 入口 `workspace.js:1154`（`#btn-density`，在页面模板字符串里，**不在 index.html**）；处理器 `workspace.js:1019-1026`；状态 `state.js:20`（`density:"cozy"`，无持久化）。
- 读取点：`list.js:30`（`ROW_HEIGHT={cozy:36,compact:26}`）、`list.js:37,265-267,395-396,426-429`；`relate.js:28,34,37-40,135,144`；`workspace.js:740,1311`。
- CSS：`style.css:637,641-645,653,661-662,1120,1132`（`.compact-list` 共 9 条）。
- `viz/treemap.js` 完全不读 density（不受影响）。

## 三、设计决策（计划 D3-1…D3-6，直接执行）

- **D3-1** 默认密度 = cozy（行高 36px）。依据：compact 会 `display:none` 掉占比条并让占比列 `width:0`（信息损失）、收益仅 1.38×、cozy 虚拟滚动窗口 DOM 行数更少、既有探针默认口径即 cozy。
- **D3-2** `.side-rail` 由固定 300px 改区间自适应（`clamp(280px,22vw,380px)` **或** `grid-template-columns: minmax(0,1fr) minmax(300px,26vw)`），并保留 1366×768 紧凑档既有收缩规则。
- **D3-3** 扫描态信息分层：状态行改 `flex-wrap`，「总进度 · 已完成 x/y 盘 · 当前盘」独立成行，耗时/ETA 移到第二行或进度条右侧；**禁止**靠 `white-space:nowrap` 硬挤。
- **D3-4** 所有可能溢出的文本必须显式选择「换行」或「省略号」；**禁止**裸 `nowrap` + 无 overflow。
- **D3-5** 概览卡头三按钮改为不挤压标题的布局（同行 flex + wrap，或收进「⋯」菜单）。
- **D3-6** 密度开关整体删除：不留隐藏开关、不留 CSS 类、不留状态字段。

## 四、硬性约束与红线

1. **不得**破坏 `u42:573-578` 的 P6 断言（1366×768 右栏无内滚）。若新布局在该断言下仍内滚，必须同时调整**内容预算**或与维护者确认后更新断言，**不得**直接改断言数字了事。
2. **不得**删除 `.donut-legend-calibre` 节点及文案（`u68a:86-129` 断言）。
3. **不得**改动 `@media (max-height:820px)` 既有收缩语义（`u24:369-375` 断言紧凑档环形 112px、卡 padding 6/12）。
4. **不得**为了「看起来不挤」而删除信息（导出按钮、ETA、chips 都必须在，只是布局更好）。
5. 删密度开关时**不得**顺手改右栏紧凑档规则（两者无关，分变更集提交以便分别回退）。
6. **红线 A · 探针有效性自证**：新增 `p03_rail_layout_probe.mjs` 必须先在**修复前代码**上跑出违规（溢出/重叠/内滚/竖排），修复后为 0；若修复前也抓不到 → 探针口径不合格，不得宣布成功。
7. **红线 B · 用户真实数据目录零写入**：跑测前后以「`%LOCALAPPDATA%\PythonDiskScanner` 文件清单 + 尺寸 + mtime」对照自证零变化（隔离 `LOCALAPPDATA` + `DSA_SNAPSHOT_DIR` 启动服务；探针默认桩态）。
8. 探针 `finally { browser.close() }`；默认 `headless: true`；参数统一 `--base` / `--out`；无残留 chromium。
9. 不触碰 Everything 进程与用户自带 Edge；不按镜像名批量杀进程。
10. Git：一变更集一提交；提交信息 `阶段P3变更集N：<内容>（<关键文件>）`；禁止 `push --force`、禁止改写已发布历史；禁止提交 `%TEMP%` 产物与 `_p3_progress.md`。
11. 收尾清进程/端口（只清自己启动的）、清 `%TEMP%` 自产产物，贴出**清理前后**进程/端口清单。
