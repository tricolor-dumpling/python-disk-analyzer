### 1.1 覆盖问题

### 1.2 根因（施工前在 stage-p3 代码上逐条复核）

- `app.py:910-918`（缓存命中 / 异步任务路径）与 `app.py:984-996`（同步路径）均写死
  `compare.diff_from_current(..., leaf_only=True)` + `rows = compare.top_growth(report, 100)`；
- `compare._merge` 无 `depth`、无 rollup，`_leaf_keys` 只回答"是不是叶子"；
- `_merge` 对两侧键并集**每键都产行**（`delta` 可为 0）；
- `top_growth` 按**有符号 delta 降序** → 零行排在所有正增量之后、负增量之前（正增量 <100 条时
  零行补位；零行 ≥100 条时负增量被整段截断）；
- 前端 `compare.js` 无任何深度控件，全量入表、空态仅在 `rows.length === 0` 时显示、
  摘要卡只统计切片内 rows（与 `delta_total` 自相矛盾）。

### 1.3 与计划文档的出入（以代码为准，已在报告与计划文档同处登记）

### 1.5 设计决策落定（D4-1…D4-6）

| 决策 | 落定 |
|---|---|
| D4-1 聚合在后端、排序/截断之前 | `compare._rollup` 在 `_build_rows` 之前折叠键集合；`_merge_from_rows` 才排序/截断 |
| D4-2 `depth` 语义 | 可选 int ≥1；**不传 = 现状叶子口径**（`depth: null` 回显）；非法入参 400，不静默降级 |
| D4-3 零增量 | 后端 `drop_zero` 在排序/截断前过滤；`top_growth(order_by="abs")` 正负同榜；**默认值一字不改** |
| D4-4 空态判据 | 前端基于**过滤后**行集；文案区分「确实无变化」与「已隐藏 N 条零变化」 |
| D4-5 摘要口径 | 响应 additive 返回 `rows_total`/`zero_count`/`zero_total`/`max_growth`/`max_release`/`depth`（全量聚合行口径） |
| D4-6 下钻交互 | **页内下钻**：行点击 → 以该目录为新根重新对比（后端把基线行按新根收窄）+ 面包屑逐级返回；**不选**「跳工作台浏览」（与用户"支持进入更深目录"的诉求不符） |

### 1.6 施工中的两处追加处置（如实登记）

1. **`compare._merge` 内部拆分**（`_build_rows` / `_merge_from_rows` / `_summarize`）：D4-5 要求
   汇总字段取「全量聚合行」口径，而 `_merge` 的既有 2 元组返回契约被 `tests/test_compare.py`
   既有用例锁定，故把「产行」与「排序+截断」拆开、由公开函数在**同一次产行**上同时取行与汇总
   （不做二次遍历）。`_merge` 的签名、返回结构与默认行为未变。
2. **下钻的基线收窄**（`app._scope_baseline_rows`）：`/api/compare` 的「当前」侧取自
   `fullscan.result(root)`；下钻换根后若基线仍是整树，会产生整片幻影「已删除」行
   （P4 基线实测：下钻 `D:\apps\framework\core` 返回 4 行假行、`Σ(delta) = −220`）。
   收窄**仅当请求 root 是快照根的严格子目录时生效**；同根（旧契约唯一覆盖面，含大小写差异）
   或非子目录时原样返回同一列表对象 → 不传新参的既有响应逐字段不变（§3.1 证明）。

| 位置 | 改动 | 说明 |
|---|---|---|

| `_norm_key` / `_relative_depth` / `_ancestor_at_depth`（新） | 路径层级工具 | `_ancestor_at_depth` 按 **normcase 长度不变** 的特性在原串上切片，**保留原大小写**（避免把 `D:\Apps` 折成 `d:\apps` 污染行路径） |
| `_rollup(mapping, root, depth)`（新） | 折叠到相对根第 N 层 | 目标键在 → 取**该键自身值**（目录值已含后代）；目标不是键（层级缺口）→ 取组内**顶层成员**之和；更浅的折叠目标若被更深目标覆盖则不入行集（O(n·深度) 祖先集合，与 `_leaf_keys` 同思路）；根行（层级 0）不进结果 |

| `_summarize(rows, depth)`（新） | 全量口径汇总 | `rows_total`（零过滤/切片前）/`zero_total`/`max_growth`/`max_release`/`depth` |
| `_normalize_depth(depth)`（新） | 参数校验 | None 或 int ≥1；bool/0/负数/字符串 → `CompareError` |
| `_merge` | 签名 additive `drop_zero=False`；内部改调新助手 | 默认行为一字不改 |
| `compare_snapshots(...)` | 签名 additive `depth=None, drop_zero=False`；返回 dict additive 6 键 | 合计口径（`_total_from_root_rows`）仍取**原始**映射的根行 → `delta_total` 不受 depth 影响；`depth` 给定时 `leaf_only` 不参与（rollup 行集本身互不重叠） |

| 用例（depth 入参） | 返回行 | 零行 | Σ(行delta) | 残差 | delta_total | depth 回显 |
|---|---|---|---|---|---|---|

| growth `drop_zero + abs`（叶子口径） | 3 | **0** | 30 | 20 | 50 | `null` |

**硬判据逐条**：

1. `Σ(聚合行 delta) + 残差 == delta_total`——**9/9 通过**。`depth=1`（整盘）残差 = 0 → 即计划硬判据
   `Σ == delta_total` 精确成立。
2. `depth=1 行数 == 顶层目录数`——3 == 3（growth 的 `D:\apps` / `D:\data` / `D:\docs`）。
3. `zero_count == 0`（开过滤时）——3 组开过滤用例全部为 0。
4. 摘要三卡 == 后端 additive 字段——12/12 态通过（探针 J5）。

**关于「残差」口径（本轮新增的诚实记账，写入报告与探针注释）**：夹具是**合成数据**（父目录值 ≠
子项之和，例如 `D:\apps = 500` 而唯一子键 `D:\apps\framework = 300`）。真实扫描数据每目录/文件
皆有行且父含子（`scan.py` 第三阶段自底向上汇总），此时折叠不会丢字节、残差恒为 0；
夹具下被折叠祖先的「未列出直属字节」增量被显式记账为**残差**，故判据写作
`Σ(行) + 残差 == delta_total`——既不为夹具不完备开脱，也不把夹具属性误判成聚合缺陷。
`depth=1`（整盘）与 `下钻 framework\core` 两处残差为 0，可作该口径成立的正向证据。
