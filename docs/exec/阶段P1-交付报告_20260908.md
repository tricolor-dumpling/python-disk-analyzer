## 一、范围与裁定

- **覆盖范围**：问题 1 全链路修复——`fullscan.py`（结果就绪回调 + autosave_outcome）、`app.py`（`/api/fullscan/*`、`/api/save`、结果就绪自动保存回调）、`components/scan.js`（删跨进程代次闸门 + 三态展示）、`components/settings.js`、`pages/workspace.js`（三态区 + 文案）、`labels.js`（精确 reason 映射）、`main.js`（未改——现状归口后无需改）、`style.css`（.notice-success + overflow-wrap）。`snapshots.py` **零改动**（只读调用 `should_auto_save`/`is_snapshot_disabled`）。
- **冻结口径（leader 预裁定，直接执行）**：
  - **D1-1 自动保存归口=后端**：全量结果就绪由后端读取 `config.auto_save`（缺键=ON）触发一次 `_save_fullscan_result(auto=True)`；前端只展示。**必须复用** `snapshots.is_snapshot_disabled()` 与 `DSA_NO_SNAPSHOT`。
  - **D1-2 多次扫描**：每次扫描完成都尝试自动保存一次，由四原子谓词裁决；跳过**可见可补救**（扫描卡显示跳过原因 + `保存快照` 保持可用 + 「仍要保存（强制）」走 `auto=false`）。
  - **D1-3 同日同根多份自动快照**：默认不放宽（每根每日 1 份自动 + 滚动保留 10 份）。

- **leader 裁定记录**：无新裁定需求；执行中未发现推荐口径不可行，直接按预裁定落地。
- **不在范围内**：`snapshots.py` 语义改动（谓词/格式/配额/保留）零改动；`main.js:245` 文案仅注释说明归口，无实际改动（光要保留自动扫描 `pds_auto_started_v1`，该键是**会话级 sessionStorage 自动扫描**保护，非被删的跨进程代次闸门，语义不同，保留）；`tests/web/smoke.html` A1/A19/A20 与 `u32` 为既有环境挂账，不改断言（见 §三）。

### 根因（代码定位确认）

1. **主因（跨进程闸门失效）**：`scan.js` 旧 `maybePromptSave` 用 `handledScanVersion`（读 localStorage `pds_handled_scan_version_v1`）对比后端 `scan_version`；后端每进程从 0 计数 → 服务重启后首次扫描 version=1，localStorage 残留 ≥1 → `return` 静默：不保存/不提示/不报错；手动按钮虽可用但需用户手动。
2. **次因 A（跳过静默 + 手动入口禁用）**：`app.py` 旧 `_save_fullscan_result` 结尾**无条件** `mark_saved()`，跳过也消费 `save_ready` → 按钮被禁用；跳过原因笼统 `predicate_rejected`。
3. **次因 B（子页面不触发）**：完成边沿 DOM 守卫先于保存触发，`#/compare`/`#/snapshots` 完成不保存、回工作台才补。
4. **现状口径**：自动保存完全前端驱动，后端仅在 `/api/save` 被动响应。
